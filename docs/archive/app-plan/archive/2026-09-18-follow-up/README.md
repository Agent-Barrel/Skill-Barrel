# 후속 정밀 검토 질의응답

> 보존 기록: 아래는 통합 전 원문/당시 판단이다. 현재 구현 기준은 [정본 안내](../../README.md)와 decisions.csv의 후속 관계를 따른다.


시작일: 2026-09-18. 최종 답변 반영·추가 검토 마무리일: 2026-09-19. 기존 `docs/plan`의 D-000~066과 요구사항 53개·기능 61개를 기준으로 후속 판단을 한 주제씩 조사하고 기록했다. **Q-001~021과 P-001~002의 답변 기록을 마쳤으며 현재 제시한 질문 중 답변 대기는 없다.** 이번 추가 검토에서는 프로젝트 관리 종료와 공통 경험 처리의 판단을 받아 기록했고, 그 외 지금 사용자가 새로 선택해야 할 제품 정책 질문은 더 발견하지 못했다. 기존 계획·CSV 정렬과 제품 구현은 다음 세션의 작업이고, 실제 환경·기술 검증은 아래에 별도로 남긴다.

## 범위와 기록 규칙

- 이번 세션은 이 폴더의 신규 질의응답 문서만 작성·갱신한다. 기존 계획·CSV 정렬과 제품 코드 구현은 다음 세션의 작업이다.
- 다음 질문 전에 사용자 답변 원문을 저장하고 확인한다. 선택지 번호만 답한 경우에도 당시 질문·선택지와 답변을 함께 남긴다.
- 원문, 답변에서 확정된 내용, 작성자의 해석·추천, 미확정 후속 사항을 구분한다. 추천안이나 조사 결과를 사용자 확정으로 승격하지 않는다.
- 정정 답변은 이전 원문을 보존하고 대체 관계를 기록한다. 기존 기획의 동시 원장·CSV 갱신 절차보다 이번 사용자 요청을 우선한다.
- 다음 세션은 이 폴더의 원문 답변을 읽고 기존 계획과 정렬한다. 이 폴더의 Q 번호는 질의 식별자이며 기존 D 번호를 임의 재번호하지 않는다.
- `00-original-flow.md`는 D-000에 따라 다음 세션에도 원문 그대로 보존한다. 추가된 흐름·정정은 나머지 계획·명세에 반영한다. 후속 문서의 반영 대상 표기를 이 원칙과 맞췄으며 질문·답변 원문은 바꾸지 않았다.

## 추가 검토에서 확인한 정렬 주의사항

아래는 기존 결정과 이번 답변을 적용하기 위한 문서 정렬 지침이다. 새 사용자 답변이나 기술 실험 통과 기록이 아니다.

- **원래 흐름 보존:** Q-011/P-002/Q-019의 다음 세션 반영 안내에서 `00-original-flow.md`를 수정 대상으로 읽을 수 있었던 표현을 고쳤다. 원문은 보존하고 추가된 와이어프레임·디자인·이미지 공급자 정책은 나머지 계획·CSV에 반영한다. 질문과 답변의 원문은 그대로 유지했다.
- **이미 해결된 미정 표시:** Q-001의 후속 정책은 Q-002/Q-003/Q-008/Q-012/Q-017/Q-018과 함께 읽는다. P-002에 남은 제작 도구·표시 방식·실제 이미지 확보 경로는 구현 검증 또는 개별 프로젝트 입력이다. `research.md`의 초기 RES-001/003/006/008에 남은 승인·기억·Slack·프레임워크 미정 표현도 최신 D 결정으로 정렬하며 처음부터 재질문하지 않는다.
- **파일 정리 참고안의 범위:** [file-cleanup-warn.md](../baseline/file-cleanup-warn.md)의 일괄 읽기 전용·TTL·며칠간 관찰·N일 뒤 삭제는 확정된 제품 정책이 아니다. 다음 세션에는 D-062/D-063 및 04의 자원 수명 계약에 맞춰 이 참고안도 정렬한다. 불변 승인 snapshot과 사용자가 편집하는 CSV·코드 작업본을 구분하고, TTL만으로 사용 중인 자원을 삭제하지 않는다. 임시 위치로 이동한 상태를 실제 삭제 완료로 표시하지 않는다. 고정 보관 기간을 새 사용자 결정으로 추가하지 않는다.
- **프로젝트 결과와 임시 사본:** Q-013/Q-020에 따라 정식 프로젝트 저장소·Git 문서·사용할 이미지 등 결과물은 유지한다. 앱이 생성하거나 clone했다는 이유만으로 임시 clone/worktree 정리 대상이 되지 않는다. Q-020의 앱 기록 영구 삭제, Q-021의 고유 정보 제거·일반 경험 유지, D-046의 개별 기억 삭제를 각각의 범위로 표현한다.

추가 대조 범위는 시작·Git 준비와 자동 반영, 세 묶음 승인·UI/API 설계, 작업 분할·의도 확인·리뷰·검수, 다중 저장소·공통 문서, 기억·계정·비용, 중단·재개·취소·프로젝트 관리 종료, Slack·원격·첨부, 설치·업데이트·관리자 작업·정리다. 남은 실제 호환성·운영 입력은 아래 O/V 항목에서 다룬다. 이번 확인으로 새 필수 승인 관문이나 내부 에이전트 감시 기능을 추가하지 않는다.

## 다음 세션에서 진행할 일과 남은 입력

1. 이 폴더의 원문과 정정 관계를 우선 읽고, 사용자 요청대로 기존 `docs/plan`과 CSV·역할·단계·검수 조건을 정렬한다. Q-010→Q-011/Q-019, Q-001→Q-018, P-001→Q-006/Q-016, Q-020→Q-021의 보완 관계를 특히 유지한다. 기존 ID의 의미를 조용히 바꾸거나 채택하지 않은 추천을 필수 기능으로 되살리지 않는다. `file-cleanup-warn.md`와 초기 조사 기록도 위 정렬 주의사항을 적용한다.
2. 이미 받은 개별 정책 선택을 재질문하지 않는다. 정렬된 전체 명세·산출물의 검토와 개별 답변 기록을 구분하고, 다음 세션에서 사용자가 요청한 구현 범위에 따라 진행한다. 이번 문서만으로 기능명세 전체 revision 승인이나 기술 실험 통과를 새로 선언하지 않는다.
3. O-01~O-10 및 V-01~V-09의 남은 항목은 기존에 정한 시점에 해결한다. 실제 모델·effort·계정/Keychain 격리·과금 상한·CLI 질문/중단/재개·접근 통제·화면 반환·이미지 확보 경로·성능·OS 지원은 구현자가 검증한다. 실패 때문에 승인된 제품 범위를 바꿔야 할 때만 근거와 대안을 갖춘 새 판단으로 연결한다.
4. 서명 인증서·업데이트 버킷 값은 초기 서명 왕복 단계에, 실제 EC2·도메인·접속·Slack 등록 값은 배포안과 로컬 통합을 준비한 뒤 받는다. 예산 통화·시간대, 개별 프로젝트의 배포 대상·사용 계정·검증 기기는 실제 사용 설정에서 정한다. 이를 현재 인터뷰의 미답변 제품 정책으로 취급하거나 지금 비밀 정보를 요구하지 않는다.
5. 구체 파일명·문서 참조 표현·작업 크기 추정값·리뷰 세부 방식·재시도 간격·설치 도구 버전은 확정된 의도 안에서 설계·검증한다. 일반 구현 판단을 피하려고 추가 승인 관문을 만들지 않는다.

이번 세션의 수정 범위는 이 신규 답변 폴더다. 기존 계획·CSV 정렬, 코드 구현·제품 테스트·설치·계정 변경·배포는 수행하지 않았다. 마지막 확정 답변은 Q-021이며 답변 원문 `1`과 선택 범위를 2026-09-19에 저장했다. 현재 답변 대기 없이 이번 추가 정책 질의를 마쳤다. 다음 세션은 이 기록에 따라 기존 계획을 정렬한 뒤 요청받은 구현 범위를 진행할 수 있다. 실제 환경 입력과 미실험 조건까지 해결되었다는 뜻은 아니다.
