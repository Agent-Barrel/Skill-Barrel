## 질문의 범위

GitHub 계정 연결 시점은 이미 확정했다. 이번 질문은 **Git이 실제로 없는 Mac에서 누가 도구를 준비하고 관리할지** 정한다. Git과 GitHub CLI인 `gh`는 역할이 다르므로 `gh`를 설치한 것만으로 로컬 Git 작업 준비가 끝난 것으로 취급하지 않는다.

Q-002의 앱 관리 Git·gh 제안은 기술 추천으로 명시했으며 당시 번호 답변으로 확정하지 않았다. 이번에는 그중 설치·준비 정책을 별도로 제시했다. 사용자는 1안을 선택하면서 앱 전용 설치는 필수가 아니고 전역에 설치해도 된다고 보완했으며, 프로젝트에 필요한 추가 도구도 승인 후 앱이 PC에 세팅할 수 있어야 한다고 정했다. 커밋 작성자 정보와 다른 Git 호스팅 서비스의 지원 범위까지 동시에 확정한 답변은 아니다.

## 조사 근거와 추천

Q-002의 동일 주제 근거를 재사용하고 2026-09-18에 아래 공식 문서를 다시 확인했다.

- [GitHub Desktop의 dugite-native](https://github.com/desktop/dugite-native)는 앱에서 사용하는 이식 가능한 Git을 구성하는 도구 체계다. 앱 관리 Git의 참고 사례이며 사용자에게 GitHub Desktop 앱을 설치시키는 방안과 다르다. 실제 사용할 배포물·버전은 패키징·호환성·서명·배포 조건을 확인한 뒤 정해야 한다.
- [GitHub CLI 공식 설치 안내](https://github.com/cli/cli#installation)는 macOS용 사전 빌드 배포물을 제공한다. 따라서 `gh` 사용만을 위해 Homebrew를 필수로 설치할 필요는 없다. 무결성 검증 방법도 제공한다.
- [Git 공식 macOS 설치 안내](https://git-scm.com/install/mac)는 Apple Command Line Tools에 포함된 Git을 설치하는 경로를 설명한다. 앱 전용 Git 대신 Apple의 시스템 개발 도구 설치 절차를 사용하는 대안이다.

위 내용은 질문 당시의 조사·추천 근거다. **사용자는 앱이 도구를 준비하는 1안을 선택하되 앱 전용 설치로 한정하지 않았다.** 앱 전용 Git 패키지나 Homebrew 없이 설치하는 경로를 반드시 채택해야 한다고 해석하지 않는다. 구체 설치 경로와 호환성은 아직 실험으로 검증한 상태가 아니다.

## 현재 구현과의 차이

- [gitops.py](../../../../barrel/core/gitops.py)의 `git_available()`과 [preflight.py](../../../../barrel/core/preflight.py)의 기본 도구 검사는 경로 탐색을 사용한다. Git 실행 가능 여부와 필요한 명령 호환성 확인, 없는 Git의 준비까지 구현된 것은 아니다.
- `gitops.py`는 Git 오류를 반환하고 호출자가 경고로 남길 수 있도록 설계되어 있다. 새 정책에서는 실제 커밋·병합이 필수인 작업을 Git 준비 실패 상태에서 완료로 표시할 수 없다. 요구 인터뷰나 읽기 전용 조사처럼 Git 준비와 독립인 작업은 구분한다.
- 현재 `_run()`은 `git` 명령을 호출한다. 앱 관리 실행 파일을 선택한다면 기존 Git 발견·유효 경로·버전 검증을 드라이버 설정에 연결해야 한다. 이 문서에서는 코드를 변경하지 않았다.

## 사용자에게 제시한 질문

**Q-008. Git이 없는 Mac에서, 개발에 필요한 Git 도구를 어떤 방식으로 준비할까요?**

1. **앱이 필요한 도구를 자동 준비 — 추천:** Git이 없으면 검증한 Git을 앱 전용 영역에 준비하고 관리합니다. GitHub 연동용 `gh`도 필요할 때 앱이 준비합니다. 사용자가 설치 명령을 입력하거나 Homebrew·GitHub Desktop을 별도로 설치할 필요가 없게 합니다.
2. **macOS 개발 도구 설치를 안내:** Apple Command Line Tools 설치를 안내하고, 여기에 포함된 Git을 사용합니다. Git 준비를 위해 별도 개발 도구 설치 절차를 거치며, GitHub 연동용 `gh`는 필요할 때 앱이 준비합니다.

두 안 모두 기존에 호환되는 Git·gh가 있으면 우선 재사용하고 개인 설치·설정을 덮어쓰지 않습니다. GitHub 가입·연결은 계속 건너뛸 수 있으며, 연결을 선택한 사용자는 공식 브라우저 인증 절차를 진행합니다.

## 사용자 답변 원문

```text
1로 하는데, 굳이 앱 전용으로 git을 설치할 필요 있나? 어차피 설치하는거 전역에 설치해도 될거라고 생각해. gh도 마찬가지야. 그리고 npm, homebrew 같은 것도 나중에 프로젝트 작업할 때 필요해지거나 하면 사용자 승인 받고 앱이 PC에 세팅할 수 있어야 해.
```

## 답변으로 확정된 내용

1. **필요한 도구를 앱이 준비하는 1안을 선택한다.** 사용자가 도구 설치 명령을 직접 작성·실행하는 것을 필수 절차로 두지 않는다.
2. **Git·gh를 앱 전용으로 설치할 필요는 없다. 전역 설치를 허용한다.** 원래 1안의 앱 전용 영역이라는 제한을 이 답변이 보완·대체한다. 모든 환경에서 무조건 중복 전역 설치하라는 뜻으로 확대하지 않는다.
3. **프로젝트에 npm·Homebrew 같은 도구가 필요해지면 사용자 승인을 받고 앱이 PC에 세팅할 수 있어야 한다.** Git·gh 준비에만 한정된 기능이 아니다. 필요하지 않은 도구까지 처음부터 모두 설치하는 결정은 아니다.
4. 기존에 호환되는 Git·gh가 있으면 재사용한다는 공통 조건은 유지한다. 전역 설치 허용을 기존 도구·개인 설정·인증의 무조건 덮어쓰기 허용으로 해석하지 않는다.
5. GitHub 가입·연결은 건너뛸 수 있으며, 연결을 선택한 사용자는 공식 브라우저 인증 절차를 진행한다는 공통 조건을 유지한다.

## 기존 위임·설치 정책과의 연결

- [D-013](../baseline/decisions.md)의 프로젝트별 환경·행동·비용 사전 위임과 연결한다. 추가 도구를 설치·설정할 때 필요한 사용자 승인을 제품 흐름에 포함한다. 이미 승인받은 구체 범위 내의 설치 단계마다 반복 승인하는 정책으로 확대하지 않는다.
- [D-059/060](../baseline/04-resolved-details.md)의 관리자 작업 경계를 사용한다. 실제로 OS 관리자 인증이 필요한 단계는 해당 공식 절차를 따른다. 전역 설치가 항상 root 실행을 뜻하는 것은 아니며 구체 설치 방식에 맞게 처리한다.
- 전역에 도구를 설치·설정하는 것과 사용자 프로젝트·AI 계정의 정본·인증 프로필을 분리하는 것은 다른 문제다. 이번 답변으로 Codex·Claude의 기존 개인 설치·프로필 보존 정책 전체를 바꾸었다고 해석하지 않는다.
- [Q-002](002-git-github-onboarding.md)의 앱 전용 Git·gh 경로는 질문 당시 추천이었다. 다음 세션은 해당 추천보다 이번 사용자 답변을 우선한다.
- 이번 답변은 **개발 에이전트 제품이 제공할 기능에 관한 결정**이다. 이번 문서 검토 세션에서 사용자의 PC에 Git·gh·npm·Homebrew를 실제 설치하라는 지시가 아니다.

## 구현 판단과 남은 경계

- 정확한 버전·설치 경로·설치 도구·다운로드·업데이트·호환성 검사는 구현자가 실제 환경과 승인 범위에 맞춰 정한다. 앱 전용 패키징을 강제하거나 내부 설치 단계마다 제품 정책 질문을 반복하지 않는다.
- 승인받은 도구 설치·설정에 필요한 변경을 수행하되 기존 설치·설정과의 충돌·영향을 확인한다. 공식 출처·무결성·라이선스 고지와 배포 조건을 확인한다. 프로젝트별 버전 요구가 기존 PC 환경과 충돌하면 기존 작업을 보존하는 설치·실행 방법을 기술적으로 검토하고, 기존 위임 범위를 넓혀야 하는 실제 변경만 D-013에 따라 판단받는다. 전역 설치 허용을 다른 프로젝트 환경을 임의 변경하는 승인으로 확대하지 않는다.
- GitHub 브라우저 로그인, 실제 계정 확인, 자격 증명 저장은 도구 설치와 별개다. Q-002에 기록한 자격 증명 저장 위치·실패 처리 검증을 유지한다.
- 취소·다운로드 실패·오프라인·용량 부족 시 준비 상태와 필요한 행동을 표시한다. GitHub 미연결은 로컬 Git 작업을 막는 사유가 아니지만, Git 자체가 없으면 Git 작업이 성공했다고 할 수 없다.
- Git만으로 향후 모든 프로젝트의 빌드 도구가 준비되는 것은 아니다. 프로젝트 스택에 필요한 추가 도구는 이번 답변에 따라 사용자 승인을 받아 앱이 설치·설정할 수 있게 한다.
- 커밋 작성자 설정은 [Q-012](012-git-author-identity.md), GitHub 이외 서비스의 초기 지원 범위는 [Q-017](017-git-hosting-support.md)에서 확정했다. 로컬 시작 후 GitHub 연결은 Q-002의 선택 연결과 Q-003의 신규 프로젝트 자동 저장 범위를 따르며, 기존 프로젝트 업로드는 해당 프로젝트의 요청·위임을 확인한다.
