# Q-019. 이미지 생성 공급자의 자유와 웹디자인 품질

> 보존 기록: 아래는 통합 전 원문/당시 판단이다. 현재 구현 기준은 [정본 안내](../../README.md)와 decisions.csv의 후속 관계를 따른다.


- 질문일·조사일: 2026-09-18
- 상태: **답변 저장 완료 — 선택지의 GPT 전제를 정정하고 레퍼런스 기반 디자인 품질을 강조**
- 대상: 화면이 있는 프로젝트의 시각 자료 확보와 이미지 의존 작업의 진행
- 범위: 질문 당시에는 GPT 웹 생성 불가 시 대체 소재를 물었으나, 사용자는 GPT에 한정할 필요가 없으며 다양한 생성 서비스를 사용할 수 있다고 정정했다. 핵심은 모던 웹디자인 레퍼런스를 충분히 참고하고 그 기법을 적용해 AI Slop을 피하는 것이다.

## 질문 당시 확인이 필요했던 이유

- [Q-010](010-ui-design-confirmation.md)에서 사용자는 UI 품질을 위해 이미지를 활용하고, GPT 웹사이트에서 생성·다운로드하여 사용하도록 지시했다. [P-002](p002-wireframe-and-visual-workflow.md)에 해당 흐름과 조사 근거를 정리했다.
- [D-041](../baseline/04-resolved-details.md)은 승인된 범위 안의 기술 접근 변경은 진행할 수 있지만, 사용자가 반드시 지키라고 정한 방법의 변경은 먼저 판단받도록 한다. 질문 당시에는 GPT 웹사이트 지정의 의도를 확인할 필요가 있었다. 아래 답변으로 GPT를 고정하거나 우선해야 한다는 전제는 해소됐다.
- 예를 들어 랜딩페이지의 배경 사진을 확보하려다가 웹 생성 한도에 막힐 수 있다. 승인된 분위기에 맞는 기존 사진을 사용하는 것과, 브랜드 전용 일러스트를 임의의 사진으로 바꾸는 것은 결과에 미치는 영향이 다르다.
- 로그인 인계·실패 원인 조사·독립 작업 진행은 기존 결정으로 처리한다. 이번 질문은 재시도 횟수나 내부 에이전트 동작을 정하는 질문이 아니라, 최종 산출물에 사용할 이미지의 대체 범위를 정하는 질문이다.

## 조사 결과

조사일: 2026-09-18. 다음은 확인한 사실이며 사용자 선택과 구분한다.

- [OpenAI 공식 이미지 생성 문서](https://learn.chatgpt.com/docs/image-generation)는 ChatGPT 웹 대화에서 이미지 생성과 참고 이미지 활용을 지원한다고 설명한다. 웹의 사용 가능 여부와 한도는 플랜·워크스페이스 설정에 따른다. CLI의 이미지 기능이나 API 이용 조건을 웹의 사용 가능 여부로 간주하지 않는다.
- [Unsplash의 공식 라이선스](https://unsplash.com/license)는 해당 라이선스가 적용되는 이미지의 무료 이용과 상업적 이용을 허용하며, 원본에 가까운 이미지 재판매·유사 서비스 구축 등에는 제한을 둔다. 이는 무료 대체 소재의 실제 사례이며 Unsplash를 필수 공급자로 채택하는 근거는 아니다. 개별 소재의 적용 조건과 사용 목적을 확인해야 하며 유료 소재까지 무료라고 가정하지 않는다.
- 이 조사는 문서 확인이다. 이 앱의 GPT 웹 생성·다운로드 자동화, 무료 소재 검색·다운로드·프로젝트 반영을 실행해 검증한 상태가 아니다. 실제 지원 여부는 구현 시 확인한다.

## 질문 당시 추천

질문 당시에는 GPT 웹사이트 생성을 기본으로 유지하는 1안을 추천했다. **사용자는 1안·2안 중 하나를 고르지 않고, GPT를 기본으로 고정한 질문의 전제를 정정했다.** 아래 질문은 당시 원문으로 보존하며, GPT부터 시도하거나 GPT가 실패해야 다른 서비스를 쓸 수 있다는 요구로 적용하지 않는다.

## 사용자에게 제시한 질문

**Q-019. GPT 웹사이트에서 이미지를 생성할 수 없을 때, 다른 이미지로 대체해도 될까요?**

1. **디자인 의도를 유지하는 대체 허용 — 추천:** 기본은 GPT 웹사이트 생성입니다. 로그인·사용량 한도 등으로 이용할 수 없으면, 에이전트가 프로젝트의 기존 이미지나 사용 조건이 확인된 무료 이미지 중 적합한 것을 골라 진행합니다. 맞춤 생성 이미지가 꼭 필요하거나 디자인 의도가 달라지는 경우에는 사용자에게 판단받습니다.
2. **GPT 웹사이트 생성 유지:** 다른 소재로 자동 대체하지 않고, 웹 생성이 가능해지거나 사용자가 대안을 정할 때까지 해당 이미지가 필요한 작업을 대기합니다.

두 안 모두 이미지와 무관한 작업은 계속할 수 있습니다. 유료 API·소재 구매로의 전환에는 기존 비용·권한 승인 규칙을 적용하며, 필요한 이미지를 빼거나 임시 이미지로 둔 채 완료 처리하지 않습니다.

## 사용자 답변 원문

```text
GPT 꼭 아니어도 돼. Gemini nanobanana, grok, qwen... 아무거나 써도 되는데 어쨌든 중요한건 웹페이지 만들 때 AI Slop 발생 안하게 모던 웹디자인 레퍼런스를 많이 참고해서 거기서 적용한 기법들(이미지를 배경과 내용에 삽입 등)을 적용하라는거지.
```

## 답변으로 확정된 내용

1. **이미지 생성은 GPT에 한정하지 않는다.** 사용자는 Gemini nanobanana, grok, qwen 등을 예로 들며 어떤 서비스를 사용해도 된다고 밝혔다.
2. GPT를 반드시 먼저 사용하거나, GPT 웹사이트에서 실패한 경우에만 다른 생성 서비스를 사용하는 조건을 두지 않는다. 기존 Q-010의 GPT 웹사이트 지정은 이번 답변에 따라 공급자를 고정하지 않는 방향으로 정정한다.
3. **중요한 목표는 웹페이지를 만들 때 AI Slop이 발생하지 않게 하는 것이다.** 서비스 선택 자체보다 최종 웹디자인의 품질을 우선한다.
4. **모던 웹디자인 레퍼런스를 많이 참고하고, 해당 레퍼런스에 적용된 기법을 실제 결과에 적용한다.** 사용자는 이미지를 배경과 내용에 삽입하는 방식을 구체적인 예로 들었다. 레퍼런스를 수집만 하고 구현에 연결하지 않는 것으로 충족했다고 보지 않는다.
5. Gemini nanobanana·grok·qwen은 허용 가능한 생성 서비스의 예시다. 나열한 서비스를 모두 초기 필수 연동 대상으로 구현하거나 사용자에게 전부 가입시키라는 요구가 아니다.

## 기존 결정과 연결한 적용 해석

아래는 답변 의도를 작업 흐름에 반영하기 위한 해석이다. 사용자 원문에 없는 고정 도구·수치·승인 절차를 새로 확정하지 않는다.

- [P-002](p002-wireframe-and-visual-workflow.md)의 리서치에서 프로젝트의 목적·사용자·콘텐츠에 맞는 현대적인 웹디자인 사례를 폭넓게 확인한다. 참고한 화면과 채택할 기법·적용 이유를 간결하게 정리해 상세 디자인과 구현 지시에 연결한다. 조사 개수나 특정 스타일을 전역 규칙으로 고정하지 않는다.
- 이미지의 배경·본문 배치뿐 아니라 레퍼런스의 구성·정보 위계·타이포그래피·여백 등 프로젝트에 필요한 표현을 함께 검토한다. 이는 적용 예시이며 사용자가 특정 디자인 기법 목록을 확정한 것은 아니다. 이미지 추가만으로 품질 목표를 충족했다고 판단하지 않는다.
- [Q-011](011-wireframe-design-approval-flow.md)의 와이어프레임 선행과 주요 상세 디자인 승인을 유지한다. 참고한 표현 기법은 기능·사용자 흐름에 맞춰 적용하고, 구현 담당자가 승인된 디자인 의도를 임의로 바꾸지 않도록 [P-001](p001-context-and-intent.md)의 정본·참조에 포함한다.
- 이미지 생성 서비스와 실제 작업 경로는 사용 가능한 기능·계정·품질을 고려해 선택한다. 이번 답변은 특정 API 도입을 결정한 것도, 새로운 유료 구독·구매를 무제한 허용한 것도 아니다. D-013/D-033의 유효한 비용·위임 범위와 D-025의 화면 사용 규칙을 적용한다.
- 질문 당시의 무료 스톡 대체안을 번호 선택으로 채택했다고 기록하지 않는다. 다만 이번 답변의 공급자 자유·디자인 품질 원칙을 다시 GPT 실패 전용 예외로 좁히지 않는다. 소재 선택의 일반적인 세부 사항 때문에 같은 공급자 질문을 반복하지 않는다. 승인된 디자인·개별 프로젝트의 명시 요구를 바꾸어야 할 때는 기존 변경 정책으로 처리한다.
- 결과 검증에서 레퍼런스로 정리한 디자인 의도와 실제 화면을 비교하고 이미지 표시·잘림·반응형 배치·가독성 등 필요한 품질을 확인한다. [Q-006](006-native-subagent-boundary.md)·[Q-016](016-unexpected-context-compaction.md)에 따라 내부 작업 방식을 세세히 추적하는 관문이나 새 최종 사용자 승인을 추가하지 않는다.
- 최종 사용 자산은 [Q-013](013-project-specs-in-git.md)에 따라 프로젝트 자료로 관리한다. 적합한 자산을 확보하지 못한 결과를 확보 완료로 표시하지 않는 기존 원칙은 유지한다.
