# Q-012. Git 작성자 정보가 없는 PC의 변경 기록

> 보존 기록: 아래는 통합 전 원문/당시 판단이다. 현재 구현 기준은 [정본 안내](../../README.md)와 decisions.csv의 후속 관계를 따른다.


- 질문일·조사일: 2026-09-18
- 상태: **답변 저장 완료 — 1안 및 브라우저 로그인 후 자동 설정 경로 허용**
- 대상: 앱이 프로젝트의 Git 변경 기록을 만들려는데 사용할 작성자 이름·이메일이 없는 경우
- 범위: Git 커밋의 작성자 초기 설정. GitHub 가입 필수 여부, Git 설치 위치, 프로젝트 업로드 동의를 다시 묻는 질문이 아니다.

## 기존 기획과 구현에서 남은 판단

- [Q-001](001-git-delivery.md)은 비개발자 작업의 커밋·병합 관리를 에이전트에게 맡겼고, [Q-002](002-git-github-onboarding.md)는 GitHub 연결을 건너뛰어도 로컬 개발·커밋·병합이 가능해야 한다고 확정했다. 따라서 GitHub 계정 정보가 없는 상태에서도 작성자 설정을 처리해야 한다.
- Q-002는 작성자 기본값과 GitHub 연결 전후 처리 방식을 미확정으로 남겼다. [Q-008](008-git-tool-provisioning.md)의 Git·gh 전역 설치 허용은 실행 도구 설치에 관한 답변으로, 모든 저장소의 작성자 정보를 바꾸라는 지시가 아니다.
- 현재 [Git 작업 코드](../../../../barrel/core/gitops.py)는 `AUTHOR_NAME = "Barrel"`, `AUTHOR_EMAIL = "barrel@local"`을 두고 `commit()`·`commit_all()`에서 `-c user.name=...`, `-c user.email=...`을 넘긴다. 작성자 정보 없는 환경에서 커밋을 만들려는 구현이지만, 기존 사용자 설정 재사용·GitHub 연결 시 전환 정책이 확정됐다는 근거는 아니다.
- 기존 원장·아키텍처·요구/기능 CSV의 작성자 이름·이메일 관련 내용을 검색했으며 이 초기 설정 정책을 찾지 못했다. 고정된 현재 코드 값을 새 제품의 사용자 결정으로 승격하지 않는다.

예를 들어 비개발자가 GitHub 연결을 건너뛰고 앱을 처음 사용하면, 작업 이력은 계속 남겨야 하지만 사용할 개인 작성자 정보가 없을 수 있다. 이때 앱 명의로 바로 진행할지, 개인 정보를 한 번 확인할지 정하는 질문이다.

## 공식 자료로 확인한 사실

- [GitHub의 커밋 이메일 설정 문서](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address)는 커밋 이메일로 계정과 이력을 연결하고, 개인 이메일 대신 GitHub가 제공하는 `noreply` 주소를 사용할 수 있다고 설명한다. 저장소별 설정은 다른 저장소에 영향을 주지 않으며, 설정 변경 전의 커밋에는 이전 이메일이 남는다.
- [GitHub Desktop의 Git 설정 문서](https://docs.github.com/en/desktop/configuring-and-customizing-github-desktop/configuring-git-for-github-desktop)는 기존 Git 작성자 설정을 감지·재사용하고, 저장소별 이름·이메일도 설정할 수 있도록 한다. 전역 작성자 설정 변경은 다른 저장소의 기본값에도 영향을 준다. 기존 설정 재사용 및 범위를 구분하는 비교 사례다.

질문 당시에는 **기존 설정을 보존하고, 없는 경우 앱이 자동 준비하는 1안**을 추천했다. 사용자는 1안을 허용하면서, Playwright·브라우저·Computer Use로 GitHub에 이동해 사용자 로그인을 받은 뒤 나머지 설정을 자동으로 하는 경로도 허용했다. 두 경로 중 하나만 고정해야 한다고 답한 것은 아니다. GitHub 미연결 때 앱 명의로 남긴 기록을 나중에 개인 명의로 소급 변경하는 정책은 아니다.

## 사용자에게 제시한 질문

**Q-012. Git에 작성자 이름·이메일이 설정되어 있지 않을 때, 변경 기록의 작성자는 어떻게 정할까요?**

1. **앱이 자동 설정 — 추천:** GitHub가 연결돼 있으면 해당 계정 이름과 개인 이메일을 숨기는 GitHub 전용 주소를 사용합니다. 미연결이면 앱 이름으로 기록하고, 나중에 연결하면 그 이후 새 기록부터 계정 정보를 사용합니다.
2. **처음 한 번 사용자에게 확인:** 사용할 이름·이메일을 입력하거나 GitHub 계정 정보를 선택하게 하고, 설정이 끝나면 이후 작업은 자동 진행합니다.

두 안 모두 기존 작성자 설정이 있으면 재사용합니다. 앱이 새로 준비하는 설정은 해당 프로젝트에 적용하고, PC 전역의 작성자 설정이나 과거 기록은 자동 변경하지 않습니다. 사용자는 이후 설정을 변경할 수 있습니다.

## 사용자 답변 원문

```text
playwright 나 브라우저 사용, computer use 사용해서 깃허브까지 이동한 위 로그인 받고 그 뒤 세팅은 자동으로 하게해도 되고, 1번 안대로 해도 돼.
```

## 답변으로 확정된 내용

1. 사용자는 **1안의 앱 자동 설정을 허용**했다. GitHub 연결 상태에서는 해당 계정 이름·개인 이메일을 숨기는 GitHub 전용 주소를 사용하고, 미연결이면 앱 이름으로 기록할 수 있다. 나중에 연결하면 이후 새 기록부터 계정 정보를 사용한다.
2. **Playwright·브라우저·Computer Use로 GitHub에 이동해 사용자 로그인을 받고, 그 뒤 설정은 자동으로 처리하는 경로도 허용**했다. 사용자가 이름·이메일이나 설정 명령을 모두 직접 입력해야 하는 방식으로 고정하지 않는다.
3. 특정 브라우저 도구 하나나 두 경로 사이의 우선순위를 고정한 답변은 아니다. 실제 환경에 맞는 경로를 사용할 수 있다.
4. 기존 작성자 설정 재사용, 앱이 준비하는 작성자 설정의 프로젝트별 적용, PC 전역 작성자 설정·과거 기록의 자동 변경 금지, 이후 사용자 설정 변경 가능이라는 질문의 공통 조건은 유지한다.
5. Q-002의 GitHub 연결 건너뛰기 허용을 취소한 답변은 아니다. 로그인 지원 경로가 추가됐다는 이유만으로 GitHub 계정을 개발 시작의 필수 조건으로 바꾸지 않는다.

## 선택한 정책을 적용할 때의 경계

아래는 기존 결정과의 연결 및 구현 검토 사항이다. 위 답변보다 넓은 정책을 확정한 것으로 취급하지 않는다.

- 브라우저에서 필요한 로그인·MFA 등 사용자 인증을 인계하고, 확인된 연결 상태와 위임 범위 안의 후속 설정은 자동 처리한다. 기존 D-013/D-025의 로그인 인계·전경 사용·사용자 개입 시 제어 반환 조건을 적용한다.
- GitHub 웹사이트의 로그인 완료, 앱/gh의 GitHub 인증 완료, Git 원격 접근 가능, Git 작성자 설정 완료는 서로 다른 상태다. 웹 로그인만으로 뒤의 상태까지 준비됐다고 표시하지 않고 실제 사용할 경로에서 확인한다. 공식 브라우저 인증 흐름과 Git 설정을 연결하는 구체적인 방법은 구현자가 검증한다.
- 이번 답변은 미래 제품의 설정 자동화 정책이다. 이번 문서 검토 세션에서 이 PC의 브라우저 로그인·Git 설정 변경·계정 연결 작업을 실행하라는 지시로 전환하지 않는다.
- 1안의 ‘나중에 연결하면 전환’은 앱이 작성자 정보가 없어 임시로 부여한 앱 명의에 적용한다. 사용자가 직접 설정한 이름·이메일이나 기존 회사/프로젝트의 작성자 설정을 GitHub 로그인만으로 바꾸는 정책이 아니다.
- 앱 명의의 로컬 기록에는 개인 실명·이메일을 추측해서 넣지 않는다. 기술적으로 필요한 앱 식별 이메일의 구체적인 값은 구현에서 정하되 실제 사용자 계정과 연결됐다고 표시하지 않는다.
- GitHub 계정 정보는 실제 연결된 대상 계정과 확인된 식별 정보를 사용한다. GitHub 개인 이메일을 임의로 공개하거나 계정의 이메일 공개 설정 자체를 변경하지 않는다. `noreply` 주소를 사용하는 것은 익명화를 의미하지 않으며 계정 연결은 유지된다.
- 일부 작성자 설정만 있거나 기존 설정이 유효하지 않은 경우에는 완전한 설정이 있는 것으로 처리하지 않는다. 사용자 지정값과 앱 기본값의 출처를 구분하고, 기존 값과 충돌하는 변경은 구체적으로 설명해 판단받는다.
- GitHub 연결과 Git 작성자 정보는 별개의 상태다. 작성자를 설정했다고 GitHub 인증·업로드·저장소 생성 권한까지 확보됐다고 취급하지 않는다. Q-002/Q-003의 연결·업로드 정책은 유지한다.
- 기존 커밋의 작성자를 바꾸기 위한 이력 재작성·강제 푸시는 자동 초기 설정에 포함하지 않는다. 기존 변경의 원래 작성자도 보존한다.
- 원격 저장소의 작성자·서명·보호 규칙이 있으면 해당 조건을 확인한다. 작성자 이름·이메일 설정만으로 서명 검증이나 원격 병합 조건이 충족됐다고 표시하지 않는다. 회사 저장소의 요구조건을 앱 명의로 우회하는 결정이 아니다.
- 앱의 작업 이력에는 요청·실행 작업과 실제 커밋을 연결한다. Git 작성자 표기만으로 어느 사용자가 어떤 작업을 요청했는지에 관한 앱 기록을 대체하지 않는다.
- 작업용 CLI가 만드는 커밋과 오케스트레이터가 만드는 커밋도 선택한 정책과 일치하는지 결과에서 확인한다. 내부 서브에이전트의 모든 실행을 추가로 감시하는 요구로 확대하지 않는다.
