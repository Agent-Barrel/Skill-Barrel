## 기존 결정 사이에 남은 판단

- [D-008](../baseline/decisions.md)은 성공 경험을 프로젝트 간 공유하되 현재 상황에 맞는지 재판단하도록 정했다. [D-030](../baseline/02-product-decisions.md)은 검증된 성공 경험의 자동 축적을 허용한다.
- [Q-020](020-project-archive-and-removal.md)은 해당 프로젝트의 앱 내 대화·명세 사본·프로젝트 기억을 삭제할 수 있도록 확정했다. 이미 다른 프로젝트에도 쓰도록 공통 기억에 축적한 경험의 수명까지 명시한 선택지는 아니었다.
- [D-046](../baseline/04-resolved-details.md)의 개별 기억 영구삭제는 본문·파생 요약·색인·맥락 사본에 전파된다. 공통 기억 항목을 직접 삭제했을 때 이 규칙을 지켜야 한다는 점은 확정되어 있다. 이번에는 프로젝트 단위 삭제가 공통 경험 중 무엇까지 삭제 대상으로 삼는지를 정한다.
- [Q-013](013-project-specs-in-git.md)에 따라 공통 기억은 프로젝트 Git 저장소에 포함하지 않는다. 따라서 프로젝트 폴더·Git 문서를 유지하는 것만으로 공통 경험의 처리까지 정해지지는 않는다.

예를 들어 프로젝트 A에서 배운 '이런 종류의 요청 중복은 이 방식으로 방지했다'는 경험이 공통 기억에 저장될 수 있다. A의 대화와 프로젝트 기록을 삭제한 뒤에도 A의 이름·고유 코드·업무 내용 없이 일반적인 해결법을 남길지, 그 경험도 함께 삭제할지의 차이다.

## 공식 자료 조사와 추천

[Claude의 공식 기억 안내](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)는 프로젝트마다 별도의 기억 공간·요약을 두며, 개별 기억 관리와 전체 기억 초기화를 구분한다. 현행 Team/Enterprise 관리 설명에는 대화가 만료·삭제되어도 관련 기억 항목은 자동 제거되지 않고 사용자가 별도로 지울 수 있다고 안내한다. 같은 페이지의 이전 방식 설명에는 삭제한 대화를 기억 요약에서 제외한다고 되어 있으므로, 이 두 방식을 섞어 동일한 현행 정책으로 해석하지 않는다.

이는 원본 대화·프로젝트와 축적한 기억의 수명 관계를 명시해야 한다는 비교 근거다. Claude의 보존 정책을 이 앱에 그대로 적용하거나 CLI 자체 기억에 의존하자는 제안이 아니다. 이 앱은 기존 결정대로 앱 소유의 공통 기억을 사용한다.

질문 당시 **1안을 추천했고 사용자가 1안을 선택했다.** 프로젝트 정보는 삭제하면서 일반화한 개발 경험을 재사용한다는 D-008/D-030의 목적을 유지하는 방식이다. 고유 정보를 분리할 수 없는 항목은 삭제한다. 원본 검증 자료를 삭제한 경우 그 한계를 기록하는 것은 기존 증거·삭제 계약과 연결한 설계 해석이다. 해당 프로젝트에서만 얻은 일반적인 경험도 함께 삭제하는 2안은 선택하지 않았다.

## 사용자에게 제시한 질문

**Q-021. 프로젝트의 앱 기록을 영구 삭제할 때, 그 프로젝트에서 얻은 공통 성공 경험은 어떻게 할까요?**

1. **일반적인 해결법은 유지 — 추천:** 프로젝트명·고유 코드·구체적인 업무 내용은 제거하고, 다른 프로젝트에도 쓸 수 있는 일반화된 개발 노하우만 남깁니다. 고유 정보를 분리할 수 없는 경험은 삭제합니다.
2. **그 프로젝트에서만 얻은 경험도 삭제:** 일반화할 수 있는 내용이라도 해당 프로젝트에서만 얻은 공통 경험은 함께 지웁니다.

두 안 모두 다른 프로젝트에서 독립적으로 축적한 경험과 사용자가 별도로 정한 공통 선호는 유지합니다. 사용자가 공통 기억 항목을 직접 골라 삭제하는 기능도 그대로 제공합니다.

## 답변으로 확정된 내용

사용자는 **1안, 일반적인 해결법은 유지**를 선택했다. 당시 질문·선택지·공통 조건은 위에 보존한다.

1. 프로젝트의 앱 기록을 영구 삭제할 때 프로젝트명·고유 코드·구체적인 업무 내용은 공통 경험에서도 제거한다.
2. 다른 프로젝트에도 쓸 수 있는 일반화된 개발 노하우는 공통 기억에 유지한다.
3. 프로젝트 고유 정보를 분리할 수 없는 경험은 삭제한다. 해당 프로젝트에서만 얻은 경험이라는 이유만으로 일반화된 노하우까지 전부 삭제하는 2안은 선택하지 않았다.
4. 다른 프로젝트에서 독립적으로 축적한 경험과 사용자가 별도로 정한 공통 선호는 유지한다.
5. 사용자가 공통 기억 항목을 직접 골라 삭제하는 기능은 그대로 제공한다. Q-020의 프로젝트 기록 삭제와 개별 공통 기억 삭제를 같은 범위로 취급하지 않는다.

이는 앱이 소유하는 기억의 처리 정책이다. 원격 AI 공급자 자체의 학습·기억 삭제를 제어한다는 결정으로 확대하지 않는다.

## 기존 결정과 연결한 적용 해석

아래는 기존 계약과 연결할 설계 검토이며 추가 사용자 결정이 아니다.

- 프로젝트 전용 기억·공통 경험·명시적 공통 선호의 범위와 출처를 구분한다. 이름만 바꾼 프로젝트 요약을 일반적인 경험으로 취급해 삭제를 피하지 않는다.
- 공통 경험 하나에 여러 프로젝트의 근거가 연결되어 있으면 삭제한 프로젝트의 정보·근거와 다른 프로젝트의 독립된 근거를 구분한다. 다른 프로젝트의 고유 결정·코드·결과를 소급 변경하지 않는다.
- 경험을 남기는 경우에도 원본 검증 자료가 삭제된 사실과 재현의 한계를 표시한다. 없는 근거를 만들어내거나 현재 프로젝트의 검수를 그 경험만으로 통과시키지 않는다. D-008의 현재 상황 재판단을 유지한다.
- 삭제한 프로젝트 본문을 원문 링크·캐시·검색 색인·맥락 사본으로 다시 노출하지 않는다. 공통 항목 직접 삭제에는 D-046의 파생 삭제 규칙을 계속 적용한다.
- 실행 중인 다른 작업의 기억 적용 시점은 D-031을 따른다. 이미 주입된 세션에서 내용을 회수했다고 주장하지 않으며, 삭제된 본문을 재시작 때 재주입하지 않는다.
