## 다음 세션이 유지해야 할 결정

- **제품 범위:** 사내 소규모 사용·테스터용. 비개발자도 사용할 수 있는 설치형 앱. 판매·제품 회원가입·결제·홍보 사이트 제외. 사용자가 Mac 설치 파일을 배포하고, 향후 제품 구현에는 사용자가 제공할 EC2의 실제 HTTPS·Slack·복구 검증까지 포함한다.
- **실행 구조:** Apple Silicon/macOS 15+ 목표, 검증한 조합만 지원. Rust core·SQLite 정본, Tauri에 번들한 React 내장 콘솔, 같은 React의 중앙 HTTPS 콘솔. 로컬 앱 시작에 Node/Vite/Python 상주 서버 불필요. 중앙은 TypeScript/Node·Fastify/WebSocket·Slack Bolt·PostgreSQL 기본안이며 Mac에서 outbound TLS 연결한다.
- **원래 flow:** 신규/유지보수 사전 평가(Astra medium) → 근거를 갖춘 요구 인터뷰/승인 → 기능 인터뷰/승인 → 기술 조사/스택 승인 → 충분한 작업·의존성·검증 계획 → 실제 구현·테스트·필요한 설치/배포/실사용 검증 → 필수 기준 충족 시 자동 완료. 세 승인은 revision 버튼이며 자연어 답변으로 대체하지 않는다. 바뀌지 않은 유효 승인·조사는 재사용한다.
- **기억·정책:** 명시 공통 선호·검증된 성공 경험 자동 축적, 추론 선호는 확인 전 후보. 사용자 변경은 다음 작업부터/영향 작업 중지 후 적용 선택, AI 자동 갱신은 새 CLI 세션부터. 작업의 승인·위임·예산 revision을 재시작/계정 변경으로 확대하지 않는다. 사용중지와 영구삭제를 분리한다.
- **실행 판단:** 프로젝트별 변경 보존·시작 브랜치는 실행 시 질문. 독립성을 확인한 read/write/외부 자원만 병렬. 의존 문서 변경·승인이 선행한다. 실패는 원인·다른 접근부터 검토하고 유효 대안 소진 후 방향을 질문한다. 승인 범위 안 방법 변경은 설명 후 진행, 사용자 필수 방법 변경은 먼저 판단받는다. 승인 전 최소 기술 실험은 별도 공간·기존 비용/권한 안에서 수행한다.
- **CLI·비용:** Codex stdio, Claude JSON 우선·PTY 보완. 공식 변경 없는 CLI와 공식 로그인, 선택한 개인 설정만 도입, 필요시 별도 앱 관리 버전. 구독 경로에 Claude bare나 조용한 API 전환 금지. 모델 기본값·실제 지원·계정/Keychain 격리·청구 유형을 구분한다. 추가 AI 지출은 명시 허용+workspace 월예산, 엄격/추정 모드. 선충전도 소비월 계상, 월 변경에도 미확정 예약 유지.
- **원격·Slack:** 인터넷 HTTPS·Mac에 등록한 브라우저만 접근, VPN 필수 아님. Mac 오프라인 일반 콘솔 수정 없음. Slack은 선택 기능, Mac에서 확인한 본인 계정만 제어, DM 기본/프로젝트별 채널 선택, 요청별 thread. 암호화 전달 대기 최대 7일. 수락 전 편집/삭제는 대체/취소, 수락 후는 변경 요청/명시적 중단 안내이며 경합은 로컬 영속 receipt로 판정한다.
- **설치·권한·업데이트:** 최초 서명·공증 DMG, 업데이트는 Tauri `.app.tar.gz`/`.sig`와 CDN 정적 JSON. 버전별 동의·검증·작업 drain·helper/DB 호환·재시작 건강 확인. 일반 core/UI/CLI는 사용자 UID, SMAppService 번들 root helper는 서명된 caller와 한정 위임 operation만 실행한다. 최초 관리자 승인·TCC/SIP 제약을 없앨 수 있다고 약속하지 않는다.
- **첨부·정리·백업:** 이미지/PDF/CSV/텍스트 지원. 명시한 후속 소비자를 추적하고 마지막 필요한 사용 뒤 앱 사본 삭제. 모든 작업의 임시파일·로그·worktree·캐시·CLI 버전·업데이트 잔여물을 owner/consumer/lease로 관리한다. 사용자 원본·활성 자원·필수 결과 보호, 삭제 실패는 영속 기록·재시도. 백업은 OS에 맡기며 앱 자체 자동 백업·암호화 내보내기·복원은 만들지 않는다.

## 승인 상태·남은 입력

D-021의 초기 요구사항 기준선과 후속 개별 답변은 확정됐다. 기능 CSV의 행 상태는 그 동작/방법의 결정 상태이며 **기능명세 전체 revision 승인이나 기술 검증 통과를 뜻하지 않는다.** Rust/Tauri/React·Tauri updater 등 이미 선택한 방향을 재질문하지 않는다. 다음 제품 구현 세션에서는 기존 승인을 재사용하고 아직 없는 전체 기능명세 승인·구체 스택 호환 검증을 해당 진입 조건으로 다룬다. 이번 문서 편집 요청을 대신 제품 실행 승인으로 해석하지 않는다.

## CSV 형식과 변경 절차

공통 7열은 `대분류,중분류,소분류,기능명,주체,상세설명,처리규칙` 순서로 유지한다. requirements는 11열, features는 15열, model-routing은 19열이다. UTF-8 BOM·CRLF·쉼표 구분·모든 필드 큰따옴표 인용·한 물리 행 한 항목을 유지한다. ID는 재번호하지 않으며 복수 근거/요구 참조는 `;`로 구분한다. 기존 앱의 18열 기능 런타임 스키마와 다르다.

결정·연구 → 요구사항 → 기능 → 검수기준·증거를 추적한다. `상태`는 명세 결정 상태이며 실행 대기/완료·메시지 전달 상태와 분리한다. 새 답변을 받으면 04의 원장에 먼저 기록하고 관련 CSV·02/03·README를 같은 작업 구간에서 갱신한다. 다음 질문 전 저장 여부를 확인한다. 일부 반영이 미완료면 해당 파일·남은 일을 명시한다.
