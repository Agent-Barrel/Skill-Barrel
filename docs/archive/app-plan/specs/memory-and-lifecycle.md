# 기억·재개·취소와 프로젝트 수명

근거: D-007~009/D-030/D-031/D-046/D-055 및 Q-007/Q-009/Q-020/Q-021. 명세 결정 상태·작업 실행 상태·프로젝트 수명·전달 상태를 별도로 기록한다.

<a id="memory"></a>
## 기억의 범위와 적용

| 종류 | 저장·참조 규칙 |
| --- | --- |
| 프로젝트 정본 | 해당 프로젝트의 요구·기능·스택·결정·작업 증거. 버전과 출처를 보존하고 다른 프로젝트로 자동 복사하지 않는다. |
| 명시한 공통 선호 | 사용자가 공통으로 적용하겠다고 표현한 선호. 범위·출처·유효 버전을 기록하고 자동 축적한다. 특정 프로젝트 요청을 전체 선호로 승격하지 않는다. |
| 추론한 선호 후보 | 추론 근거와 확신 수준을 표시한다. 확인 전에는 확정 선호나 승인 근거로 사용하지 않는다. |
| 검증된 성공 경험 | 당시 환경·문제·시도·결과·검증 증거·적용 조건을 함께 저장한다. 성공했다는 에이전트의 자기 보고만으로 검증 완료 처리하지 않는다. |

새 맥락 묶음은 현재 요청·프로젝트의 명시적 결정, 적용 가능한 공통 선호, 조건이 맞는 경험 순으로 근거를 구성한다. 이 순서는 누락이나 모순을 숨기는 우선순위가 아니다. 승인된 프로젝트 결정과 새 공통 원칙이 충돌하면 영향을 설명하고 판단받는다. 요약은 원문·검증 증거를 가리키며 불확실성과 생략된 범위를 포함한다.

직접 수정·삭제 때는 영향받는 작업과 다음 중 하나를 기록한다. 초기 추천 설정은 `매번 묻기`이며 사용자가 기본 동작을 바꿀 수 있다.

| 선택 | 실행 의미 |
| --- | --- |
| 다음 작업부터 | 이미 실행에 들어간 TaskContract는 고정된 기억·정책 revision을 유지한다. 아직 시작하지 않은 작업은 새 revision으로 재평가한다. 기존 작업의 재시작·계정 전환도 같은 작업이면 기존 유효 정책을 재구성한다. |
| 관련 작업을 중지하고 지금 적용 | 영향을 받는 작업에 중단 요청을 보내고 중단 확인·현재 외부 효과 확인 후 새 revision으로 재계획한다. 중단 요청 성공을 확인하기 전에는 ‘적용 완료’로 표시하지 않는다. 완료된 외부 동작은 소급 취소되지 않는다. |
| AI 자동 갱신 | 이미 열린 CLI 세션에는 중간 주입하지 않는다. 새 CLI 세션 시작 시 적용 가능한 최신 기억을 선택한다. 다만 기존 작업의 승인·위임 범위를 자동으로 확대하거나 사용자에게 고정된 정책 revision을 덮어쓰지 않는다. |

권한·비용·승인 범위라는 이유만으로 제품이 무조건 기존 작업을 즉시 중지하는 예외를 넣지 않는다. 예를 들어 예산 변경을 다음 작업부터 적용하면 기존 예약과 정책을 분리해 보여준다. 외부에서 실제 자격 증명이 철회되거나 공급자가 실행을 거부한 경우는 기억 적용 선택과 다른 실행 실패이며, 불가능한 작업을 계속 시도하지 않는다.

사용중지는 새 맥락 검색·추천에서 제외하고 과거 근거를 유지한다. 영구삭제는 앱 관리 본문·파생 요약·색인·맥락 사본을 제거하고 삭제 사실만 남긴다(D-046). 기존 작업 유지 선택도 이미 주입된 맥락을 회수했다는 뜻은 아니며, 삭제된 본문을 재시작 때 다시 주입하지 않는다. 앱 자체 백업/내보내기/복원은 제공하지 않고 OS 백업에 맡긴다(D-055). 앱 밖의 백업·공급자 세션에 남은 과거 본문까지 제거를 보장하지 않는다. [삭제·정리 계약](resources.md#lifetime)을 따른다.

처음에는 SQLite의 구조화 필터·FTS·원문 참조를 사용하고 검색 품질 평가가 필요성을 입증하면 임베딩을 추가한다. 외부 전송·비용을 먼저 도입하지 않는다. 프로젝트 문서의 Git 작업본과 앱 불변 snapshot/승인은 [문서 계약](repositories.md#documents)에 연결하며 두 개의 독립 정본으로 운영하지 않는다.

<a id="recovery"></a>
## 체크포인트와 재개 시점

체크포인트에는 작업 상태·입력/승인/기억/위임 revision·계정/모델·예산 예약·CLI 세션 참조·검증·미확정 외부 효과·대기 질문·inbox/outbox·자원 consumer를 저장한다. 앱 종료 의도, 작업 일시중지/취소, 프로젝트 보관/삭제와 미반영 변경 선택도 영속화한다. CLI 네이티브 재개와 앱 정본으로 새 세션을 구성한 재개를 표시상 구분한다.

| 중단 사유 | 앱을 다시 실행했을 때 |
| --- | --- |
| 장애·Mac 재시작·업데이트 | 마지막 상태/복구 가능성을 확인한 후 유효한 작업 자동 재개 |
| 사용자가 앱의 종료 선택 | 상태를 복구하되 사용자가 계속하기를 누를 때까지 실행 대기 |
| 작업 일시중지·취소 | 자동 재개하지 않음. 취소 변경분은 별도 보관/폐기 선택 유지 |
| 답변·승인·권한·예산·외부 결과 대기 | 기존 대기 조건이 해결될 때까지 계속 대기 |
| 보관·삭제 프로젝트 | 오래된 이벤트/재시작만으로 관리·작업을 다시 시작하지 않음 |

직접 종료 의도는 종료 처리 전에 기록하고 계속하기가 수락되면 해당 대기만 해제하는 구현 계약을 둔다. 그 사이 crash가 생겨도 의도를 잃지 않는다. 재개 이유를 판정할 증거가 불충분하면 기존 상태·receipt 확인 전 실행하지 않는다. 앱 다시 열기·로그인 시 앱 자동 시작·작업 재개는 서로 다른 행동이다. 창 닫기의 트레이 유지와 자동 시작 옵션은 변경 가능한 UI 기본안이며 Q-007 답변으로 강제하지 않는다.

재시작 시 `running`을 일괄 재실행하지 않는다. 이전 프로세스 생존·실제 종료·lease 세대·파일 상태·외부 receipt를 확인한 뒤 새 attempt를 발급한다. lease 만료만으로 프로세스가 멈췄다고 가정하지 않는다. 이미 성공한 병합/배포는 반복하지 않고 결과 불명은 `recovery_required`로 남긴다.

같은 작업의 승인·위임·예산 revision은 재시작·계정 변경으로 확대하지 않는다. 유효한 평가·계획·의도 검토는 재사용하고 변경/누락 영향만 재검토한다. 삭제한 기억 본문은 다시 주입하지 않으며 재구성 한계를 표시한다. 앱 자체 백업/내보내기/복원은 만들지 않고 OS 백업에 맡긴다. 정상 crash·DB migration 복구는 유지한다.

<a id="lifecycle"></a>
## 취소·보관·영구 삭제의 범위

| 행동 | 실행·기록 | 파일·외부 효과 |
| --- | --- | --- |
| 작업 취소 | 바로 중단을 시작하고 미반영 변경 요약·보관/폐기 선택. 선택 전 보존. | 사용자 원래 변경·이미 반영된 코드/배포·설치 도구는 자동 복구/제거하지 않음. |
| 변경 보관 | 기준 revision·실제 diff·미완료 상태·필수 증거 보존. | 전체 worktree/빌드 캐시를 무기한 보관할 필요는 없음. 재사용 전 현재 의도/입력 확인. |
| 변경 폐기 | 실제 중단·소유권·다른 소비자 참조 확인 후 해당 미반영 변경만 삭제. | 사용자/다른 작업 변경이나 소유권 불명 변경을 삭제하지 않음. |
| 프로젝트 보관 | 기본 목록에서 숨기고 이력 유지. 명시적 다시 열기 지원. | 로컬 코드·Git 문서·원격 저장소·배포 자원 유지. |
| 프로젝트 앱 기록 영구 삭제 | 대화·명세 사본·프로젝트 기억과 파생 요약/색인/맥락 사본 삭제. | 정식 프로젝트 저장소·Git 문서·원격/배포 서비스·설치 도구 유지. |
| 개별 기억 영구 삭제 | D-046의 해당 항목 본문·파생 삭제. | 프로젝트 삭제의 일반화 예외로 개별 삭제를 무력화하지 않음. |

취소 요청과 중단 완료는 구분한다. 보관/폐기 답변을 기다리느라 새 작업을 계속 배정하지 않는다. 보관한 미완료 변경은 자동 재개/병합하지 않고 검수 완료로 표시하지 않는다. 진행 중 외부 효과는 조회해 실제 결과를 남기며 되돌리기/외부 자원 폐기는 범위를 정한 별도 작업이다.

프로젝트 보관/삭제는 진행 작업과 미반영 변경을 기존 중단·보존 절차에 연결한다. 삭제를 먼저 완료했다고 표시해 보존할 결과를 잃지 않는다. 보관을 해제해도 취소/일시중지·기존 대기는 자동 해제되지 않는다.

프로젝트 앱 기록 삭제 후 비용·미확정 예산 예약을 취소/무료 정산하지 않는다. 재정산·외부 효과 복구·중복 명령 거부에 필요한 최소 식별 기록은 본문과 분리해 남긴다. 삭제한 내용이 캐시·색인·맥락·이전 링크에서 다시 노출되지 않게 한다. 실제 삭제 실패는 재시도 상태로 남기고 완료로 표시하지 않는다.

앱이 생성/clone한 정식 프로젝트 폴더·코드·Git 문서도 보존 대상이다. 임시 사본과는 [자원 수명](resources.md#lifetime)으로 구분한다. 앱 밖 Git 이력·Slack 메시지·공급자 기록·OS 백업까지 지웠다고 표시하지 않는다.

## 프로젝트 삭제와 공통 성공 경험

Q-021에 따라 프로젝트명·고유 코드·구체 업무 내용은 공통 경험에서도 제거하고, 일반화된 개발 노하우만 유지한다. 고유 정보를 분리할 수 없는 항목은 삭제한다. 이름만 바꾼 프로젝트 요약을 일반 경험으로 남기지 않는다. 해당 프로젝트에서만 얻은 경험이라도 일반화 가능하면 유지할 수 있다.

여러 프로젝트의 근거가 있는 경험은 삭제 프로젝트의 고유 정보/근거와 다른 프로젝트의 독립 근거를 분리한다. 다른 프로젝트의 독립 경험·명시적 공통 선호·기존 결정/코드는 소급 변경하지 않는다. 원본 검증 자료가 삭제된 사실·재현 한계를 남기며 없는 근거를 만들어내지 않는다. 현재 작업 적합성과 실제 검수는 다시 확인한다.

사용자가 공통 기억을 직접 골라 삭제하면 D-046의 본문·파생 전파가 그대로 적용된다. 실행 중 적용 시점은 D-031을 따르되 이미 주입된 세션에서 회수했다고 주장하지 않고 새 세션/재개에 삭제 본문을 넣지 않는다.
