## 공식 드라이버·설정·계정

Codex는 공식 app-server stdio, Claude는 공식 stream-json을 기본 어댑터로 한다. Claude PTY는 JSON 경로에서 지원하지 못하는 대화형 기능을 보완한다. 시작 전에 `DriverCapabilities`로 CLI 버전, 인증 유형, 실제 모델·effort, 질문·permission·cancel·resume 지원을 확인한다. JSON 경로가 불명확한 실행 중 실패했다고 즉시 PTY로 같은 작업을 다시 실행하지 않는다. 먼저 기존 프로세스 중단과 외부 효과를 확인한 뒤 새 attempt에서 앱 ContextBundle을 재구성한다.

Claude `-p`는 구독 인증 동작을 실제로 검증한다. `--bare`는 OAuth/Keychain 구독 로그인 경로를 읽지 않으므로 이 제품의 구독 격리 기본값으로 쓰지 않는다. 구조화 권한 요청과 사용자 질문의 왕복을 검증하며 `--permission-prompts none`, `bypassPermissions` 등으로 대화를 없애서 검증 성공으로 처리하지 않는다. Codex도 설치 버전의 protocol/schema와 승인 정책을 확인하며 기존 Python의 `never`·`danger-full-access` 기본값을 그대로 이식하지 않는다.

설정은 앱 관리 기본 환경 → 사용자가 선택 도입한 항목 → 평가한 프로젝트 지침과 적용 가능한 관리 정책의 실제 우선순위를 기록한다. 이 순서는 공식 CLI의 관리 정책 우선순위를 바꾼다는 뜻이 아니다. 개인 디렉터리·자동 훅·MCP·메모리를 통째로 복사하지 않는다. `setting-sources`·명시적 settings·strict MCP 등 사용 가능한 공식 옵션을 검증하고 차단할 수 없는 묵시 로딩은 숨기지 않는다. 설정 도입 확인과 계정 로그인은 별도 UI다.

실행파일은 알려진 설치 위치와 명시적 경로 입력을 통해 찾는다. GUI 앱에서 셸 dotfile을 실행해 PATH를 얻는 방식을 필수로 하지 않는다. 기존 CLI가 호환되면 재사용하며 앱 관리 버전이 필요할 때만 공식 출처·무결성·라이선스를 확인해 별도 경로에 둔다. 활성 세션이 사용하는 버전은 정리·교체하지 않는다. 인증 비밀을 앱 메모리 원장·로그·중앙에 복제하지 않는다. `CODEX_HOME`/`CLAUDE_CONFIG_DIR` 분리와 실제 Keychain/계정 격리는 각각 검증한다.

프로필마다 불필요한 상속 인증 환경을 제거하고 선택한 `CODEX_HOME`/`CLAUDE_CONFIG_DIR`를 CLI 자식 프로세스에 전달한다. 계정 별칭·설정 폴더 차이만으로 Keychain 격리나 실제 청구 유형을 확정하지 않는다. 역할별 요청 모델·effort와 실제 선택·확인 시각·전환 이유를 기록하고 미지원 강도를 조용히 낮추지 않는다.

Codex stdio를 제품의 인터넷 중계 프로토콜로 그대로 노출하지 않는다. Claude.ai 토큰 수집이나 중앙 구독 프록시를 도입하지 않으며 공급자 조건은 출시 버전에서 재확인한다. 한 공급자만 있어도 전체 흐름을 시작할 수 있고 교차 조사 제한을 표시한다. 최소 권장 Codex 1 + Claude 1, 추가 권장 Codex 2 + Claude 1 또는 Codex 1 + Claude 2는 강제 구독이나 처리량 보장이 아니다.

계정·모델 전환 전 기존 프로세스·외부 효과를 확인하고 앱 정본으로 새 attempt를 구성한다. 권한·정책 거절을 공급자 전환으로 우회하지 않는다. 내부 서브에이전트의 개별 사용량 원장을 새로 강제하지 않아도 앱이 배정한 실행의 허용 비용 경계는 유지한다.

Git/gh·프로젝트 빌드 도구의 전역 설치 허용(Q-008)은 위 AI CLI의 개인 설정 보존·앱 관리 버전 정책을 변경하지 않는다. [저장소 도구 계약](repositories.md#tools)을 적용한다.

## 모델 티어·최신 지원 확인과 명확한 작업의 효율 배정

2026-09-19 사용자 정정 D-067 원문:

> 내가 전에 astra xhigh 랑 fable 5.1 max 가 같은 티어라고 했는데, astra max 와 fable 5.1 max 가 같은티어야. astra max 가 있는지 모르고 그렇게 말한거고, 가벼운 작업은 claude 보다는 astra medium 정도로 수행하는게 좋은 것 같아. 이거 docs/plan 의 문서들에 반여해줘

현재 고품질 운영 대응은 **Astra max ↔ Fable 5.1 max**다. D-022의 이전 xhigh 대응과 이를 사용한 조율·GPT 조사·대체값을 max로 정정한다. SOT 관리·독립 리뷰·설계의 Astra 기본값도 같은 기준으로 정렬하되, 이들 역할에 모델을 배정한 것은 기존처럼 설계 기본값이다. 동일 티어는 사용자 운영 기준이며 모든 작업의 동일 성능·비용이나 모든 계정의 지원을 입증한 벤치마크 결과가 아니다.

D-068은 위 D-067 중 **가벼운 작업에 Astra medium을 고정 우선하는 부분만** 대체한다. 작고 세부 지시가 명확한 작업은 Sonnet 5 등의 효율 모델을 사용해 토큰을 절약할 수 있다. 명확성은 정확한 문서 revision·입출력·오류 동작·구현 단계·검수 방법·미해결 결정·위험 범위로 판단하며, 파일 수나 작은 분할 또는 `lightweight` 표시만으로 입증되지 않는다. 인증·권한·보안·데이터 무결성·외부 효과나 복잡한 판단이 포함되면 해당 고품질 역할을 유지한다. 사전 평가 RTE-011·의도 확인 RTE-013의 Astra medium, 고품질 Astra max/Fable 5.1 max와 고강도 SOT·독립 리뷰·설계는 변경하지 않는다.

다음 순서는 D-068의 최신 모델 확인·효율 모델 허용을 적용하는 **설계 기본값**이며 사용자가 이 세부 순서나 모델 간 동등성을 확정한 것은 아니다. 새 계획에 적용할 정책 revision에 고정하고 사용자 명시 설정을 보존한다.

| 역할 | 정확한 모델 ID와 effort 후보 순서 |
| --- | --- |
| 일반 구현 RTE-003 / 구현 대체 RTE-007 | `claude-opus-5-5 max` → `claude-opus-5-5[1m] max` → `claude-opus-5-5 xhigh` → `claude-opus-5-5[1m] xhigh` → `claude-opus-5 max` → `claude-opus-5 xhigh` → `gpt-6-sol max` |
| 명확하고 영향·검수 난도가 낮은 실행 RTE-017 | `claude-sonnet-5 medium` → `claude-sonnet-5[1m] medium` → `gpt-6-sol medium` → `gpt-6-astra medium` |

모델명·세대·`[1m]` 변형은 별도 실제 ID다. 공식 CLI/계정에서 현재 확인한 정확한 ID와 지원 effort를 선택하고, 프리셋에 적혀 있다는 이유만으로 지원을 확정하지 않는다. 새로운 모델은 현행 목록·CLI 버전·계정·확인 시각과 유효기간으로 발견한다. 오래된 `opus` 같은 family 값은 현재 허용된 목록이 한 실제 모델만 가리킬 때만 해석하며 여러 세대로 갈리면 확인이 필요하다. 저장된 값이 현재 목록에 없어도 숨기거나 기본값으로 되돌리지 않는다.

위 표는 목표 실제 ID를 나타낸다. 현재 기본 프리셋의 기존 Opus 5와 마지막 Astra 후보는 호환용 family `opus-5`·`astra`를 유지하며, 허용 카탈로그에서 각각 `claude-opus-5`·`gpt-6-astra`에 해당하는 실제 후보가 하나일 때만 해석한다. 여러 context 변형이 함께 있으면 모호한 선택을 거부한다. 이 두 호환 후보를 정확한 ID가 고정된 것으로 표시하지 않으며, 새 사용자 선택은 모두 확인한 actual_id로 정규화한다.

허용 대안은 실제 지원·품질·계정·예산과 전환 사유를 확인한 뒤 선택한다. 명시적 사용자 선택을 몰래 최신 모델로 바꾸거나 실행 중 Task의 정책을 새 기본값으로 덮어쓰지 않는다. 수행 중 위험·복잡도·미해결 결정이 커지면 기존 평가·역할·계획을 재검토하고 어느 경로에서도 필수 검수·승인을 생략하지 않는다.

max는 이제 선택된 기본값이며 실제 계정/CLI 호환 확인은 별도다. 미지원 max를 조용히 xhigh로 낮추어 동일 티어라고 표시하지 않는다. Astra high ↔ Fable 5.1 xhigh의 별도 경험적 선택과 ultra 옵션은 이번 정정과 구분한다. Q-019의 이미지 생성 공급자 자유는 유지한다. 앱이 결정적으로 처리할 수 있는 저장·중단·검증을 매번 AI 호출로 바꾸는 요구도 아니다.

## 선택적 Jev 라우팅 보조

D-068은 Jev를 라우팅 판단의 보조로 사용할 수 있도록 허용한다. Jev는 코드 생성 역할을 대체하지 않는다. 공식 [API](https://docs.typesafe.ai/api)는 `POST https://api.typesafe.ai/v1/systemone`에 Bearer API key와 `model/state/questions`를 받고 typed 답변을 돌려준다. [모델 문서](https://docs.typesafe.ai/models)의 2026-09-23 확인 버전은 `jev-1.13.0`이며 alias는 바뀔 수 있으므로 요청/응답 버전과 평가 기준을 기록한다. 이는 해당 계정의 접근 권한이나 실제 응답 품질 검증을 뜻하지 않는다.

기본 라우팅은 Jev 없이도 동작한다. 선택적 연결에는 키·별도 서비스 이용 및 요약 외부 전송 설정·추가 AI 비용 허용·전체 월예산을 확인한다. 전체 계약·코드·대화·첨부·경로·비밀 대신 목적·명확성·영향·검수·미해결 결정의 필요한 구조화 요약만 전송하고 입력 hash·정책 revision과 결합한다. 비용이 작다는 이유로 무료 처리하지 않는다. 엄격 예산의 상한 근거가 없는 경로는 기존 계약대로 비활성화한다.

호스트가 먼저 경량 배정의 필수 증거·위험·계정/실제 모델/effort·정책·권한·예산을 검사한다. Jev는 이 조건을 통과한 후보에 대한 제한된 분류만 제공하고 자격을 새로 부여하거나 거절을 우회하지 못한다. 키/접근 미설정·시간 초과·한도·잘못된 응답·불확실·상충 판단에는 사유를 남기고 기존 정책으로 돌아간다. 오래된 결과로 새 입력·정책을 배정하지 않는다. 전체 deadline과 재시도 상한을 두며 응답 유실을 미청구로 단정하지 않는다.

Choice의 확률 분포와 confidence, Noul의 yes 확률을 구분한다. confidence는 의미적 정확성 보장이 아니며 threshold는 실제 작업군으로 검증해야 한다. 공급자도 [주입·수치·간접 추론 등 한계](https://docs.typesafe.ai/model-jaggedness/jev-1.13)를 명시한다. 구조화 출력 보장을 올바른 위험 판정·권한 보장으로 확대하지 않는다. **Jev API 어댑터·비용 원장·실제 계정/품질 검증은 후속 구현이며 완료로 표시하지 않는다.**

D-068/D-069의 원문 출처로 이번 지속 목표에 추가된 사용자 문장을 보존한다. 모델 순서와 어댑터 세부 설계는 위 계약 및 아래 외부 작업 절에서 구분한다.

> 지금 Opus 5.5 나 GPT Sol 6 등이 신규로 나왔으니 이런 최신 내용을 에이전트 제품에서 확인하고 모델 라우팅이 가능하도록 해야하고, 모델라우팅 판단은 jev 사용해도 좋을 것 같아.
>
> 에이전트의 자체 기능으로 slack 을 사용하게 하는 것보다, slack MCP 호출하고 에이전트가 호출한 에이전트에게 slack 메시지 보내게 해도 좋을 것 같아. 외부 연동은 이렇게 유연하게 하도록 하는게 좋아보여.
>
> 또, 각 작업에서 해야할 일들의 단위가 작고 세부 내용까지 명확히 정해져 있으면 그 지시를 명확히 따를 수 있는 하위 모델로(sonnet 5 등) 작동하게 해서 토큰을 아껴도 좋아. 토큰 효율성과 작업의 명확성을 모두 얻을 수 있는 방향으로 작동하게 설계해줘.

사용자가 추가로 공유한 Jev 링크: [Introducing System One Models & Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev). 링크 공유는 계정 연결·유료 API 실행·신규 가입이나 의미적 정확성 보장을 뜻하지 않는다.

## 월간 추가 AI 비용

한 작업공간의 전체 프로젝트가 월간 추가 AI 지출 원장을 공유한다. `구독 포함 사용량`, `API 가격 환산액`, `실제 추가 청구액`, `아직 확정되지 않은 추정액`을 다른 필드로 표시한다. 선충전 크레딧도 소비한 달에 계상하고 구매·충전은 별도 표시해 이중 차감하지 않는다(D-050). 두 작업이 같은 잔여 예산을 동시에 예약하지 않도록 실행 전 예약과 정산을 트랜잭션으로 처리한다. 월 변경으로 미확정 예약을 소멸시키지 않는다.

| 모드 | 실행 조건과 한계 |
| --- | --- |
| 엄격 | 명시적 추가 과금 허용·월예산이 있고, 경로별 강제 상한 또는 보수적인 최대 비용을 확인할 수 있어야 한다. 청구 지연·미확정 최대 비용 때문에 한도를 보장할 수 없는 유료 경로는 사용하지 않고 이유를 표시한다. 토큰 카운터만으로 실제 청구액의 절대 상한을 보장하지 않는다. |
| 추정 | 동일한 허용·월예산 아래 추정 비용을 예약하며 실행할 수 있다. 추정 근거·오차·청구 지연·초과 가능성을 보여주고, 잔여 예산을 초과할 것으로 예상되는 새 작업은 대기시킨다. 무제한 지출 허용 모드가 아니다. |

로컬 예산은 이 제품이 시작한 사용을 통제한다. 같은 AI 계정을 다른 앱에서도 쓰는 경우 공급자의 신뢰할 수 있는 전체 사용량·상한이 없으면 계정 전체 청구를 보장할 수 없다. 프로필 별칭이나 ChatGPT 로그인 확인만으로 추가 사용료가 전혀 없다고 판정하지 않는다.

외부 서비스 작업은 프로젝트별 `환경·대상·행동·비용·기간/유효 조건` 위임을 사용한다. 이미 위임한 범위는 반복 확인하지 않는다. 범위를 넓혀야 하면 실제 변경 대상·영향·비용을 제시한다. 로그인·MFA·OS 권한과 전경 화면 사용 시간 합의는 별도 조건이다. 제품의 회원가입·과금 기능 제외가 AI 공급자·Slack·인프라 서비스의 인증이나 요금까지 없애는 것은 아니다.

`BudgetReservation`은 workspace·정책 revision·통화·시간대·소비 기간·예약액·근거·정산 상태를 가진다. 충전 구매와 실제 소비를 다른 ledger 종류로 기록한다. 공급자 사용 증거가 기간별 분리를 제공하면 그 기간에 귀속하고, 월 경계를 넘은 사용의 정확한 분리가 불가능하면 미확정으로 표시해 보수적으로 예약한다. 월 변경으로 기존 미확정 예약을 소멸시키거나 다음 달 잔여액을 이중 사용하지 않는다. 통화·시간대는 유료 기능 첫 설정에서 선택하고 월별 기준을 고정한다. 실패한 작업도 실제 유료 소비를 계상하며 취소·실패만으로 미확정 예약을 무료 정산하지 않는다.

사용자가 ‘다음 작업부터’를 선택한 변경은 실행 중 TaskContract의 기억·위임·예산 revision을 바꾸지 않는다. 같은 작업의 앱 재시작·계정 전환도 이를 유지한다. 다만 영구삭제한 기억 본문은 다시 주입할 수 없으므로 삭제 표식과 재구성 제한을 표시한다. 자동 기억 갱신은 새 CLI 세션에만 적용하며 권한·비용 범위를 확대하지 않는다. 공급자가 실제 권한을 철회한 경우는 정책 적용 유예와 달리 실행 불가 상태다.

추가 지출 꺼짐·켜는 경우 엄격 모드 우선 제시는 설계 기본값이다. 통화·시간대는 유료 기능을 사용할 때 선택하며 환율·추정 여유율은 실험과 설정으로 정한다. 고성능 SOT 관리나 이미지 공급자 자유는 새 비용 허용이 아니다.

<a id="delegation"></a>
## 외부 작업·설치·화면 인계

실행할 대상·행동·환경·비용·유효 조건을 구체화한 뒤 기존 위임에 포함되면 자율 수행한다. 확장이 필요하면 실행 가능한 변경안과 영향·비용을 먼저 준비해 판단받는다. Git push가 배포를 유발하면 실제 외부 효과도 같은 위임으로 판단한다. 설치 도구·이미지 생성 서비스도 적용 대상이다.

사람에게 필요한 로그인·MFA·OS 승인은 구체적으로 인계하고 이후 허용된 설정·연결 검증은 앱이 수행한다. AWS 장기 IAM 키 발급을 유일한 방식으로 고정하지 않는다. CLI·API·격리 브라우저를 우선 검토하고 실제 전경 화면 조작은 작업·범위·사용 가능 시간대를 합의한 후 수행한다.

전경 작업은 독점 예약을 사용한다. 미합의·예약 전·시간 만료에는 조작하지 않으며 사용자 복귀 시 입력 중지·제어 반환을 확인하고 진행 상태를 보존한다. 반환 감지·권한·OS 창 대응은 V-06의 실제 검증 대상이다. 무제한 root 권한으로 로그인·화면/TCC 제약을 대신하지 않는다.

외부 효과는 실행 전 의도·고정 idempotency key, 실행 후 receipt·상태 조회를 기록한다. 성공 응답 유실은 재조회하고, 멱등/조회 수단이 없어 불명확하면 복구 대기로 남긴다. 원격 명령 중복 방지가 외부 시스템의 정확히 한 번 실행까지 보장하지 않는다.

<a id="external-adapters"></a>
## 교체 가능한 외부 도구와 에이전트 위임

D-069에 따라 외부 작업은 내장 서비스별 동작만으로 고정하지 않고 선택한 MCP·공식 CLI/API 등의 어댑터로 수행할 수 있게 한다. 예를 들어 에이전트가 Slack MCP를 호출하거나 호출한 하위 에이전트에게 승인된 목적지의 메시지 전송을 맡길 수 있다. 이 구조는 기존 FEAT-035/036/052와 REQ-031/032/045의 확장 설계이며 모든 외부 서비스를 한 번에 연동하거나 공급자 내부 하위 에이전트를 전수 감시하는 요구가 아니다.

사용자가 선택한 연결·인증 주체·실제 도구/schema·출처/version과 프로젝트별 대상·행동·환경·비용·유효기간을 결합한다. 하위 에이전트 위임은 부모의 범위를 유지하거나 좁히며 새 외부 권한을 만들지 않는다. 호스트는 실행 직전에 현재 task/run/attempt·lease·위임·종료/업데이트 조건을 검사하고 정확한 입력과 고정 operation ID를 기록한다. 수신 확인·에이전트의 전송 주장·실제 provider receipt를 구분한다. 응답 유실 뒤 새 ID나 다른 어댑터로 같은 효과를 재실행하지 않고 조회 또는 복구 대기를 사용한다.

도구 연결·개인 설정 도입과 실제 실행 허용은 별도다. 선택하지 않은 MCP/자동 훅·스킬·인증을 묵시 도입하지 않으며 현재 차단된 도구를 단순히 풀어 위임·비용 검사를 생략하지 않는다. 일반 상태 전달에 불필요한 모델 호출을 추가하지 않고 문맥 판단이 필요한 작성/요약을 작은 작업으로 분리한다. Slack 본인 명령 인증·7일 큐·승인 revision·첨부 확보는 [별도 수신 계약](remote-and-slack.md#external-output)을 유지한다. **범용 도구 실행/위임 어댑터와 실제 MCP·Slack 계정 왕복은 후속 구현·검증 범위다.**

2026-09-23 구현 근거: [로컬 MCP 연결·호출 원장·복구](../../implementation/external-tools.md)를 추가했다. 실제 macOS 실험에서 인증정보 격리 한계가 확인되어 일반 앱의 실행은 차단한다. 합성 프로토콜 왕복은 위임·실제 외부 효과·Slack 연동 완료 근거가 아니다. 위 요구 범위를 축소하는 결정은 아니다.

같은 날 [원격 HTTP MCP 연결과 사용자 지정 호출](../../implementation/remote-tools.md)을 추가했다. 호스트 HTTPS/DNS/TLS·별도 Keychain binding·정확한 도구/입력·dispatch intent·프로젝트 전체 Unknown 차단을 구현했다. 내장 화면의 직접 호출은 자동 모델 실행·부모 위임·실제 외부 대상/비용 강제·provider receipt 조회를 대신하지 않으며, 해당 후속 요구는 유지한다.

2026-09-23 후속 구현: [요청에 고정한 자동 MCP 동작](../../implementation/agent-operations.md)을 신규 Codex typed callback에 연결했다. 사전 준비한 정확한 입력·기존 부모 위임·추가 비용 0의 사용자 검토 근거·고정 서버 receipt 규칙을 사용한다. Task 수정/재계획의 동일 의미 ID, 실제 transport 종료, 필수 외부 의무의 Task/요청 완료 검사를 포함한다. 이 범위는 재사용 가능한 서비스 계약·유료 비용 원장·Unknown 조회·계정 principal 검증·Claude/하위 에이전트와 실제 Slack 왕복 요구를 축소하거나 완료로 바꾸지 않는다.

같은 날 후속으로 재사용하는 고정 서비스 계약과 **검수·Git 반영 후 결과 전달**을 연결했다. 기존 구현 응답의 요약과 앱이 확인한 결과를 구분하고, 한 문자열 필드만 byte 한도 안에서 한 번 동결해 현재 마무리 worker의 소유권으로 전송한다. 일반 결과 전달에 추가 모델 호출은 없다. 전체 요청 결과의 별도 작성·임의 JSON 작성·유료 비용·실제 서비스 계정/영수증 검증과 위의 미완료 범위는 유지한다. 실제 검증의 경계는 [자동 동작 구현 기록](../../implementation/agent-operations.md)을 따른다.
