# Q23. spike에 쓸 준비물

- 질문일: 2026-10-12
- 관련: [Q22-2](q22-2-launcher-residency.md), [구현 준비 점검](../readiness-2026-10-12.md)의 "Before the spike", [skill-plugin/validation.md](../skill-plugin/validation.md#tasks)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "요약"은 찾아보기 편하도록 붙인 것이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

[Q22-2](q22-2-launcher-residency.md)의 답을 받은 뒤 물었다. 그 전에 Q22와 Q22-2에서 AI가 꺼낸 방향(상주 실행기, Slack에서 실행 시작)은 넣지 않고 지금 설계대로 둔다고 알렸다.

설계 판단은 남은 것이 없고, spike를 돌릴 때 필요한 사실 세 가지만 묻는다고 했다.

1. **Slack 워크스페이스:** Barrel 봇을 설치할 워크스페이스는 어디인가. 거기에 앱을 직접 설치할 수 있는가, 관리자 승인이 필요한가.
2. **유지보수 과제용 레포:** 유지보수 과제에 쓸 기존 레포는 무엇인가.
3. **여러 저장소 과제용 프로젝트:** 예전 Q-014에서 지금 진행 중인 프로젝트도 상위 폴더 아래 레포 여러 개로 구성돼 있다고 했다. 그 프로젝트를 여러 저장소 과제에 써도 되는가.

지금 답해도 되고, spike를 시작할 때 알려 줘도 된다고 적었다.

## 사용자 답변 (2026-10-12, 원문 그대로)

```text
1. [워크스페이스 이름] 워크 스페이스인데, '[사용자 이름]'을 제외한 다른 사람들은 테스트에 사용하지말고, 현존하는 채널들도 테스트에 사용하지마. 테스트 필요하면 새로 만들어서 해. 앱 설치 바로 되는진 모르겠는데? 아마 될걸. 안해봐서 모르겠어.
2. 니가 테스트 용으로 가벼운거 하나 만들어
3. 테스트 용으로는 쓰지마. 중요한 프로젝트 진행 중이니까 그냥 그것도 테스트 용으로 하나 만들고, 이 스킬 완성에 집중해.
~/Desktop/Projects/ 에 테스트용 프로젝트 만들면 돼.
```

> **원문을 바꾼 곳 (2026-10-13):** 이 레포는 공개다. 그래서 사용자가 고른 대로([아래](#mask)) 원문의 워크스페이스 이름과 사람 이름만 `[워크스페이스 이름]`, `[사용자 이름]`으로 바꿨다. 나머지는 받은 그대로다. 실제 값은 레포 밖에 둔다.

## 요약 (원문이 우선)

- **Slack 워크스페이스:** 원문의 워크스페이스를 쓴다.
  - 테스트에는 원문에 적힌 한 사람 말고 다른 사람을 쓰지 않는다.
  - 지금 있는 채널은 테스트에 쓰지 않는다. 테스트에 채널이 필요하면 새로 만든다.
  - 앱을 바로 설치할 수 있는지는 해 보지 않아서 모른다. 아마 될 것이다.
- **유지보수 과제용 레포:** AI가 테스트용으로 가벼운 레포를 하나 만든다.
- **여러 저장소 과제용 프로젝트:** 진행 중인 중요한 프로젝트는 테스트에 쓰지 않는다. 이것도 테스트용으로 하나 만든다. 이 스킬을 완성하는 데 집중한다.
- **위치:** 테스트용 프로젝트는 `~/Desktop/Projects/`에 만든다.

## 이 답에 따른 정리 (AI 분석, 원문이 우선)

- **Slack에서 테스트할 때:**
  - 봇이 초대하거나 멘션하는 사람은 등록한 사용자 한 명뿐이다. 설계도 등록한 사용자의 글만 받는다(예전 결정 D-043, [slack.md](../skill-plugin/slack.md#security)). 다른 구성원은 채널에 초대하지도, 멘션하지도 않는다.
  - Barrel이 새로 만드는 비공개 채널만 쓴다. 설계상 프로젝트마다 `barrel-<project>` 채널을 새로 만든다.
  - 이미 있는 채널에는 글을 쓰지 않는다. "사용하지마"를 읽기까지 포함한 것으로 보고, 테스트 중에는 공식 Slack MCP로도 기존 채널을 읽지 않는다(AI 해석).
  - 앱을 바로 설치할 수 있는지는 spike 항목 19(Slack 앱 만들기)에서 확인한다. 관리자 승인이 필요하다고 나오면 그때 사용자에게 알린다. 무료 플랜의 앱 수 제한(spike 항목 25)도 함께 확인한다.
- **테스트용 프로젝트** ([validation.md](../skill-plugin/validation.md#tasks)의 실제 과제):
  - 모두 `~/Desktop/Projects/` 아래에 만든다.
  - **유지보수 과제:** AI가 가벼운 레포를 하나 만든다. S2 온보딩이 기록할 거리가 있도록 코드, 테스트, 빌드·테스트 명령, 몇 개의 커밋을 갖춘다.
  - **여러 저장소 과제:** 상위 폴더 아래에 기획 레포 하나와 코드 레포 둘(예: 프론트엔드, 백엔드)을 테스트용으로 만든다([Q17](q17-restore-archived-decisions.md) 1번, [Q17-2](q17-2-repo-list-config-and-updates.md)의 `repos.json`).
  - **새 컨셉 과제:** skill을 `~/Desktop/Projects/`에서 실행해, Barrel이 만드는 새 폴더도 그 아래에 생기게 한다.
  - **원격:** 테스트용 레포의 GitHub 원격은 만들지 않는다. push나 PR 전달을 시험해야 하면 그때 먼저 묻는다. 원격 레포를 만드는 일은 바깥에 공개되는 작업이기 때문이다.
- **쓰지 않는 것:** 사용자가 진행 중인 프로젝트와 기존 레포는 테스트에 쓰지 않는다.
- **공개 레포 주의:** 이 레포는 공개다. 이 기록의 원문에는 워크스페이스 이름과 사람 이름이 들어 있었다. 다른 문서에는 옮기지 않았다. 커밋하기 전에 가릴지 물었고, 사용자는 둘 다 가리기를 골랐다([아래](#mask)).

## 공개 레포에서 가리는 범위 (확인 질문과 답)

정본 개정을 시작하기 전, 이 기록을 처음 커밋하기 전에 물었다.

### 질문 (사용자에게 보낸 내용)

아직 커밋하지 않은 Q23 기록의 답변 원문에 Slack 워크스페이스 이름과 사람 이름이 그대로 들어 있다. 레포가 공개라서 첫 커밋 전에 정해야 한다.

질문 창에 보인 선택지 이름과 설명:
- `둘 다 가리기 (추천)`: 원문의 두 이름을 [워크스페이스 이름], [사용자 이름]으로 바꾸고, 바꾼 사실을 기록에 적는다. 실제 값은 spike 때 쓰도록 레포 밖(이 Mac의 메모리)에만 둔다. 이전에 레포를 옮길 때도 회사 이름이 파일에 없는지 확인했다.
- `원문 그대로`: 답변 원문을 바꾸지 않는다는 기록 원칙대로 커밋한다. 공개 레포에 두 이름이 그대로 남는다.
- `워크스페이스만 가리기`: 회사 워크스페이스 이름만 [워크스페이스 이름]으로 바꾸고, 사람 이름은 그대로 둔다.

### 사용자 답변 (2026-10-13, 원문 그대로)

선택지를 골랐다.

```text
둘 다 가리기 (추천)
```

### 요약 (원문이 우선)

- 원문의 워크스페이스 이름과 사람 이름을 모두 가린다.
- 실제 값은 레포 밖에만 둔다.

### 이 답에 따른 정리 (AI 분석, 원문이 우선)

- **기록 원칙의 예외:** 답변 원문을 고치지 않는다는 원칙에 예외가 하나 더 생겼다. 이전 제품 이름(`[이전 이름]`, [Q17-2](q17-2-repo-list-config-and-updates.md))에 더해, 이 기록의 두 이름을 가렸다.
- **실제 값:** 이 Mac의 CLI 메모리에 적었다. spike를 시작할 때 거기서 읽는다. 레포의 어떤 파일에도 쓰지 않는다.
