# Q22-2. 실행기를 skill과 별개로 늘 띄워 두는가

- 질문일: 2026-10-12
- 관련: [Q22](q22-slack-new-requests.md)의 후속, [Q03-3](q03-3-launcher-and-slack.md), [Q11](q11-launcher-topology.md), 예전 결정 Q-007([결정 원장](../../archive/app-plan/decisions.csv)), [skill-plugin/launcher.md](../skill-plugin/launcher.md#process)(AI 기본값 1번), [구현 준비 점검](../readiness-2026-10-12.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "요약"은 찾아보기 편하도록 붙인 것이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

[Q22](q22-slack-new-requests.md)의 답(skill 없이 봇이 동작할 수 있느냐는 되물음)에 먼저 답했다. 내용은 Q22 기록의 "AI가 답한 내용"에 있다. 이어서 이 질문을 했다.

### 왜 지금 묻는지

- 이 답 하나로 두 가지가 정해진다.
  - 재부팅이나 실행기 장애 뒤에 Barrel이 스스로 다시 떠서 하던 실행을 이어 가는지
  - Slack에서 새 요청을 받을 수 있는지(Q22)
- 예전 결정 Q-007은 장애나 재시작 뒤에 하던 작업을 자동으로 이어 가기로 했다. 다만 "로그인할 때 자동 시작"은 정하지 않았다고 적혀 있다.
- Q11에서 고른 선택지의 "분리 실행이 안 되면 launchd로 띄운다"는 실행기를 띄우는 방법에 관한 것이었다. 재부팅 뒤에 다시 뜨는지는 정하지 않았다.

### 다른 도구 조사 요약 (2026-10-12 확인)

- **Claude Code 백그라운드 세션:**
  - 감독 프로세스는 필요할 때만 뜨고, 로그인할 때 저절로 뜨지 않는다.
  - 컴퓨터를 다시 켜면 돌던 세션은 멈춰 있고, 사용자가 다시 붙거나 답을 보내야 이어진다. 잠자기로는 멈추지 않는다.
  - ([문서](https://code.claude.com/docs/en/agent-view))
- **Docker Desktop:** "로그인할 때 시작" 설정이 있고 기본값은 꺼짐이다. 자주 쓰는 사용자에게는 켜 두기를 권한다. ([문서](https://docs.docker.com/desktop/settings-and-maintenance/settings/))
- **macOS:** 로그인할 때 뜨는 백그라운드 항목을 등록하면 macOS 13부터 "백그라운드 항목 추가됨" 알림이 한 번 뜬다. 시스템 설정 > 일반 > 로그인 항목에서 끄고 켤 수 있다. ([Eclectic Light, 비공식](https://eclecticlight.co/2023/02/15/controlling-login-and-background-items-in-ventura/))

### 선택지

- **A 늘 띄워 둔다.**
  - 로그인 항목으로 한 번 등록한다. 로그인할 때 뜨고, 죽으면 다시 뜬다.
  - 재부팅이나 장애 뒤에도 하던 실행을 이어 간다. 사용자가 멈춘 실행은 그대로 둔다(Q-007).
  - 실행이 없을 때도 Slack 글을 받는다. 그래서 Q22의 "Slack에서도 받기"가 가능하다. 기존 프로젝트의 새 요청을 받고, 버튼으로 한 번 확인한다.
  - 대신 할 일이 없을 때도 실행기 하나가 상주한다.
- **B (추천) 할 일이 남아 있을 때만 띄워 둔다.**
  - 로그인 항목은 A와 똑같이 한 번 등록한다. 로그인할 때 떠서, 진행 중이거나 멈춘 실행이 있으면 남고 없으면 바로 끝난다. 할 일이 남아 있는 동안에는 죽어도 다시 뜬다.
  - 재부팅이나 장애 뒤에도 남은 실행을 이어 간다.
  - 할 일이 없으면 상주하는 것이 없다.
  - 실행이 없을 때는 Slack 글을 받을 곳이 없다. 그래서 새 요청은 skill로만 시작하고, Slack은 진행 중인 실행에 주는 지시만 받는다.
- **C 자동으로 띄우지 않는다 (지금 설계).**
  - skill, Barrel.app, `barrel` 명령을 쓸 때만 실행기가 뜬다.
  - 재부팅이나 장애 뒤에는 이 중 하나를 실행할 때까지 모든 실행이 멈춰 있다. 그동안 Slack에서 "재개"나 "상태"를 보내도 답하지 않는다.
  - 새 요청은 skill로만 시작한다.

추천 이유:
- Q01의 목표는 사람이 붙어 있지 않아도 끝까지 진행되는 것이다. 재부팅 한 번에 사용자가 돌아올 때까지 멈추는 C는 이 목표와 맞지 않는다.
- B는 Q-007대로 남은 일을 스스로 이어 가면서도, 할 일이 없으면 아무것도 상주하지 않는다. skill이 시작점이라는 지금 구조도 그대로다.
- Slack에서 새 요청까지 받고 싶으면 A를 고르면 된다고 적었다.

질문 창에 보인 선택지 이름과 설명:
- `남은 일 있을 때만 (추천)`: 로그인 항목으로 한 번 등록합니다. 진행 중이거나 멈춘 실행이 있으면 재부팅·장애 뒤에도 다시 떠서 이어 갑니다. 없으면 바로 끝납니다. 새 요청은 skill로만 시작합니다.
- `늘 띄워 두기`: 로그인할 때 뜨고 항상 상주합니다. 재부팅 뒤 이어 가기에 더해, 실행이 없을 때도 Slack에서 기존 프로젝트의 새 요청을 받습니다(버튼으로 확인).
- `자동 시작 안 함 (지금 설계)`: skill·Barrel.app·barrel 명령을 쓸 때만 뜹니다. 재부팅·장애 뒤에는 그때까지 모든 실행이 멈추고 Slack에도 답하지 않습니다.

## 사용자 답변 (2026-10-12, 원문 그대로)

선택지를 고르지 않고 직접 썼다.

```text
아니 이렇게 할거였으면 그냥 별도 앱으로 만드는게 깔끔한 설계지. 이 레포에선 스킬로 작동하게 할거라니까 왜 자꾸 내가 시키지도 않은 방향으로 가려고 하는거야?
```

## 요약 (원문이 우선)

- 이렇게(실행기를 로그인 항목으로 등록해 띄워 두는 식으로) 할 거였으면 별도 앱으로 만드는 편이 깔끔한 설계다.
- 이 레포에서는 스킬로 작동하게 한다.
- 시키지 않은 방향으로 가지 말라.

## 이 답에 따른 정리 (AI 분석, 원문이 우선)

- **Q22와 Q22-2에서 AI가 꺼낸 방향은 모두 넣지 않는다.**
  - 실행기를 로그인 항목으로 등록하지 않고, skill과 별개로 상주시키지 않는다.
  - Slack에서 새 실행을 시작하지 않는다.
- **지금 설계를 그대로 둔다.**
  - 실행기는 skill이 띄운다(Q03-3). Barrel.app과 `barrel` 명령도 실행기가 꺼져 있으면 띄운다. 분리 실행이 살아남지 못할 때만 launchd로 띄운다(Q11에서 고른 선택지).
  - Slack은 진행 중인 실행에 주는 지시만 받는다. 새 요청은 skill로 시작하고, 요청마다 새 실행이 된다(Q18).
  - 재부팅이나 실행기 장애 뒤에는 skill, Barrel.app, `barrel` 명령으로 실행기가 다시 뜰 때 남은 실행을 이어 간다(AI 기본값 1번, 예전 결정 Q-007의 자동 재개).
- **정본을 고칠 때 바꿀 곳:** [launcher.md](../skill-plugin/launcher.md#process)는 launchd로 띄우는 경우에 "로그인할 때 다시 띄운다(`RunAtLoad`)"를 적어 두었다. launchd는 분리 실행의 대안으로만 쓰고, 로그인할 때 띄우는 설정은 쓰지 않는다.
- **[Q22](q22-slack-new-requests.md)의 결론:** 선택지 B(Slack은 진행 중인 실행에 주는 지시만 받는다, 지금 설계)와 같다.
