# Q18. 같은 프로젝트에 새 요청이 오면 진행 중인 실행에 합치는가, 따로 돌리는가

- 질문일: 2026-10-12
- 관련: [skill-plugin/runs.md](../skill-plugin/runs.md#start), [open-decisions.md](../skill-plugin/open-decisions.md#ai-defaults)의 AI 기본값 35번, [Q10-2](q10-2-pc-view-stop-language.md), [Q14](q14-parallel-sessions.md), [Q17](q17-restore-archived-decisions.md), [구현 준비 점검](../readiness-2026-10-12.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "요약"은 찾아보기 편하도록 붙인 것이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

[Q17](q17-restore-archived-decisions.md)의 답을 받은 뒤 물었다.

### 왜 지금 묻는지

실행기는 한 프로젝트에서 실행이 몇 개까지 돌 수 있는지를 처음부터 알아야 한다. 그래야 실행 상태, 브랜치, Slack 보고, PC 화면의 구조를 정할 수 있다.

지금 설계(AI 기본값 35번)는 한 프로젝트에 실행을 하나만 둔다. 실행 중에 skill을 다시 부르면 새 요청은 진행 중인 실행에 지시로 들어간다. 그래서 며칠 걸리는 기능 개발 도중에 급한 버그 수정을 맡기면, 그 수정은 기능 개발이 끝날 때 함께 전달된다.

### 다른 서비스 조사 요약

- **GitHub Copilot coding agent:**
  - 이슈를 여러 개 한꺼번에 맡기면 이슈마다 브랜치와 PR을 따로 만든다.
  - 고칠 점은 그 PR에 `@copilot` 댓글로 전한다. 2026-03부터는 그 PR을 바로 고친다.
  - ([일괄 배정](https://github.blog/ai-and-ml/github-copilot/assigning-and-completing-issues-with-coding-agent-in-github-copilot/), [변경 기록](https://github.blog/changelog/2026-03-24-ask-copilot-to-make-changes-to-any-pull-request/))
- **Devin:**
  - 세션마다 VM을 따로 쓰고, 진행 중인 세션에는 메시지로 지시를 보낸다.
  - 2026-03에 한 세션이 하위 세션들에 일을 나눠 맡기고 서로 겹친 부분을 정리하는 기능이 나왔다.
  - ([Cognition 블로그](https://cognition.com/blog/devin-can-now-manage-devins))
- **Cursor:** 병렬 에이전트마다 worktree와 브랜치를 따로 쓴다. 2.0 기준 최대 8개다. ([변경 기록](https://cursor.com/changelog/2-0))
- **Codex cloud:**
  - 작업마다 레포가 담긴 샌드박스를 따로 띄워 동시에 돌린다.
  - 결과는 작업별로 diff를 보고 PR로 연다.
  - ([OpenAI](https://openai.com/index/introducing-codex/))
- **공통점:**
  - 새 요청은 새 작업이 되어 자기 브랜치와 결과물을 따로 가진다. 진행 중인 작업을 바꾸는 말만 그 작업에 보낸다.
  - 다만 동시에 많이 돌리면 나중에 합칠 때 조정 비용이 든다.

### 선택지

- **A (추천) 요청마다 새 실행을 연다.**
  - skill로 들어온 새 요청은 별도 실행으로 나란히 진행하고 따로 전달한다. 실행 브랜치, 작업 트리, 오케스트레이터가 각각 생긴다.
  - 진행 중인 실행을 바꾸고 싶으면 Slack에서 그 실행에 지시한다.
  - 두 실행은 프로젝트의 동시 개수(기본 2)를 나눠 쓴다.
  - 한 채널에 두 실행의 보고와 질문이 섞이므로 메시지마다 요청 이름을 붙인다.
  - 채널에 쓴 지시가 어느 실행 것인지는 스레드로 구분하고, 구분이 안 되면 버튼으로 묻는다.
  - 나중에 전달하는 실행은 먼저 끝난 실행의 결과를 합쳐서 맞춘다. 두 실행의 결정이 서로 부딪히면 묻는다.
  - 중지와 재개는 Q10-2대로 그 프로젝트의 실행 전체에 걸린다.
- **B 오케스트레이터가 판단한다.**
  - 새 요청이 진행 중인 실행과 관련 있으면 그 실행에 합치고, 무관하면 새 실행을 연다.
  - 어느 쪽으로 했는지 Slack에 알리고, 바꾸라고 하면 바꾼다.
  - 판단이 틀릴 수 있다.
- **C 지금 설계대로 실행은 하나만 둔다.**
  - 새 요청은 진행 중인 실행(중지된 실행 포함)에 지시로 합쳐서 함께 전달한다.
  - 따로 하려면 먼저 그 실행을 취소한다([Q17](q17-restore-archived-decisions.md)의 7번).

추천 이유: 조사한 서비스 모두 요청 하나를 작업 하나로 다룬다. 급한 수정을 긴 작업이 끝날 때까지 붙잡아 두지 않아도 된다. 예전 결정 D-023("작업 요청마다 스레드를 만들고 프로젝트를 표시한다")도 요청을 하나의 일 단위로 봤다.

질문 창에 보인 선택지 이름과 설명:
- `요청마다 새 실행 (추천)`: 새 요청은 별도 실행(브랜치·작업 트리·오케스트레이터)으로 나란히 진행하고 따로 전달합니다. 진행 중인 실행을 바꾸는 말은 Slack에서 그 실행에 보냅니다.
- `오케스트레이터가 판단`: 관련 있으면 진행 중인 실행에 합치고, 무관하면 새 실행을 엽니다. 어느 쪽으로 했는지 Slack에 알립니다.
- `실행은 하나 (지금 설계)`: 새 요청은 진행 중인 실행에 지시로 합쳐 함께 전달합니다. 따로 하려면 먼저 그 실행을 취소합니다.

요청마다 새 실행 (추천)

## 요약 (원문이 우선)

고른 선택지 A의 내용이 결정이다.
- **새 실행:** skill로 들어온 새 요청은 같은 프로젝트라도 별도 실행으로 나란히 진행하고 따로 전달한다. 실행 브랜치, 작업 트리, 오케스트레이터가 각각 생긴다.
- **진행 중인 실행 바꾸기:** Slack에서 그 실행에 지시한다.
- **동시 개수:** 프로젝트의 동시 개수(기본 2)를 실행들이 나눠 쓴다.
- **Slack:**
  - 메시지마다 요청 이름을 붙인다.
  - 채널 지시는 스레드로 어느 실행 것인지 구분한다. 구분이 안 되면 버튼으로 묻는다.
- **전달:** 나중에 전달하는 실행이 먼저 끝난 실행의 결과를 합쳐서 맞춘다. 결정이 서로 부딪히면 묻는다.
- **중지와 재개:** Q10-2대로 그 프로젝트의 실행 전체에 걸린다.

## 이 답에 따른 정리 (AI 분석, 원문이 우선)

- **바뀌는 AI 기본값:** AI 기본값 35번의 "한 프로젝트에 실행은 하나"와 "skill이 새 요청을 진행 중인 실행에 지시로 넘긴다"를 바꾼다. 해당 문장은 [runs.md](../skill-plugin/runs.md#start) 16줄과 22~24줄, [plugin.md](../skill-plugin/plugin.md#skill)의 skill 동작이다.
  - skill은 항상 새 실행을 연다. skill에서 `barrel instruct`를 부르는 경로는 없앤다. Slack 지시는 그대로 둔다.
  - 중지된 실행이 있어도 새 실행은 따로 시작한다. 중지된 실행은 재개나 취소를 기다린다.
- **보이는 곳:** 스냅샷, 진행 한 줄, PC 화면은 프로젝트의 실행을 모두 보여 주고, 실행마다 요청 이름으로 나눈다.
- **질문 머리말:** Q10의 `[{프로젝트명}-질문]`은 그대로 두고, 요청 이름을 바로 뒤에 붙인다. 한국어 모드에서는 요청 이름도 한국어 작성 세션이 만든다.
- **레인 배정:** 동시 개수와 레인은 프로젝트 단위로 두고, 실행기가 여러 실행의 말단에 고르게 나눠 준다.
- **기억:** 실행마다 자기 실행 브랜치에 `.barrel/` 변경을 커밋한다. 전달할 때 base를 다시 확인하면서 앞선 실행의 단위를 받아 오고, 새로 들어온 결정 단위와 부딪히는지 검사한다([구현 준비 점검](../readiness-2026-10-12.md)의 빈 곳 10번).
- **중지와 재개:** 중지는 그 프로젝트에서 도는 모든 실행을 멈춘다. 재개는 그 중지로 멈춘 실행을 모두 이어 간다.
- **취소:** 실행 취소([Q17](q17-restore-archived-decisions.md) 7번)는 실행 단위로 한다.
- **여러 저장소:** 여러 저장소 프로젝트([Q17](q17-restore-archived-decisions.md) 1번)에서는 실행 하나가 프로젝트의 레포들에 걸친다. 나란히 도는 실행은 레포마다 자기 브랜치를 가진다.
- 아직 `skill-plugin/`에 반영하지 않았다.
