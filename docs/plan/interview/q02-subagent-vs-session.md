# Q02. subagent와 새 세션에 각각 어떤 일을 맡기는가

- 질문일: 2026-10-06
- 관련: [어긋나는 점 2번](../README.md#conflicts)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "선택지 대응"은 찾아보기 편하도록 붙인 요약이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

### 왜 지금 묻는지

요청 원문에 "subagent 뿐만 아니라 신규 코딩 에이전트 세션도 오케스트레이션"이 있지만, 09-29 초안은 subagent를 작업 세션으로 쓰지 않았다. [Q01](q01-keep-working-scope.md)에서 "막힌 작업만 멈추고 나머지는 계속"으로 정했으니, 어떤 실행 단위가 무엇을 맡을지 정해야 한다. 이 답에 따라 오케스트레이터 재시작(어긋나는 점 3번)과 작업 분할(6번) 구조가 달라진다.

### 현재 각 실행 단위의 동작 (2026-10 공식 문서 기준)

| | Claude Code subagent | Claude Code agent teams | Codex subagent | step2step 새 세션 |
| --- | --- | --- | --- | --- |
| 맥락 | 새 맥락 | 팀원마다 독립된 Claude Code 세션 | 새 맥락 | 완전히 새 세션 |
| 결과 전달 | 요약만 부모에게 | 메시지와 공유 작업 목록 | 요약만 | 전체 기록과 파일 |
| 사용자에게 질문 | 불가(`AskUserQuestion` 제거) | 사용자가 팀원과 직접 대화 가능 | 승인 요청은 부모 쪽에 뜸 | 질문을 오케스트레이터가 받아 문서로 답하거나 사용자에게 전달 |
| 계획 승인 | plan 모드로 설정할 때만 | 리드가 검토 없이 자동 승인 | 문서에 없음 | 오케스트레이터가 계획 본문을 보고 승인 또는 반려 |
| 다른 공급자 | 불가 | 불가 | 불가 | 가능(Claude ↔ Codex) |
| 오케스트레이터 재시작 후 | 부모와 함께 끝남 | 리드와 함께 끝나고 재개 시 복원 안 됨 | 부모 세션 안의 스레드(재시작 동작 미확인) | 별도 프로세스라 계속 돎 |
| 안정성 | 공식 기능 | 실험 기능 | 공식 기능(중첩 제한 버그 보고) | CLI 화면 해석에 의존. CLI 업데이트 시 재보정이 필요할 수 있음 |

subagent 결과는 오케스트레이터 대화 안으로 들어와 그 맥락을 쓴다. 새 세션은 결과를 파일로 남기므로 오케스트레이터는 필요한 부분만 읽으면 된다. "세션은 두뇌로만 쓰고 맥락은 문서로"라는 원칙과는 새 세션 쪽이 맞는다.

출처: [Claude Code subagents](https://code.claude.com/docs/en/sub-agents), [Claude Code agent teams](https://code.claude.com/docs/en/agent-teams), [Codex subagents](https://developers.openai.com/codex/subagents), [openai/codex #46704](https://github.com/openai/codex/issues/46704)

### 선택지

- **A (추천) 일의 성격으로 나눈다.**
  - 새 세션(step2step)이 맡는 일:
    - 코드를 바꾸는 구현 작업
    - 계획 → 의도 대조 → 승인을 거쳐야 하는 작업
    - 다른 공급자가 필요한 일(Fable·Astra 조언, Claude·Codex 교차 조사)
    - 오래 걸려 오케스트레이터가 재시작돼도 이어져야 하는 작업
  - subagent가 맡는 일: 읽기만 하고 짧게 끝나며 요약으로 받아도 되는 일
    - 기억 파일의 참조를 따라가며 맥락 모으기
    - 자료 조사
    - 작업자가 아닌 쪽의 독립 검토
  - 작업 세션도 자기 안에서 subagent를 쓸 수 있다.
- **B** 모든 작업을 새 세션으로 한다. subagent는 각 작업 세션 내부에서만 쓴다.
- **C** subagent(또는 agent teams)를 기본으로 한다. 새 세션은 subagent로 안 되는 경우(다른 공급자, 재시작 후 지속, 계획 승인)에만 쓴다.

## 선택지 대응 (요약, 원문이 우선)

- **A.** 새 세션(step2step)은 구현, 계획 승인이 필요한 작업, 다른 공급자가 필요한 일, 재시작 뒤에도 이어져야 하는 작업을 맡는다. subagent는 읽기 전용의 짧은 일(맥락 수집, 조사, 독립 검토)을 맡는다. 작업 세션은 내부에서 subagent를 쓸 수 있다.

  > **이후 변경(2026-10-08):** [Q16](q16-engines-and-verification.md)에서 사용자가 일을 공급자 단위로 나누지 말라고 했다. Claude Code와 Codex는 Barrel을 돌리는 엔진일 뿐이다. 위의 "다른 공급자가 필요한 일(Fable·Astra 조언, Claude·Codex 교차 조사)"은 더 이상 공급자 기준으로 읽지 않는다. 교차 검증은 조사 뒤의 독립 검증 단계로 한다. 새 세션과 subagent는 일의 성격으로 나누되, 설정이 고른 엔진이 부모 세션과 다른 CLI이면 새 세션으로 띄운다.
