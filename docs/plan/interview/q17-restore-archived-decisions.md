# Q17. 예전 계획에서 정한 결정 중 빠진 것을 되살리는가

- 질문일: 2026-10-12
- 관련: [예전 계획의 결정 원장](../../archive/app-plan/decisions.csv), [skill-plugin/open-decisions.md](../skill-plugin/open-decisions.md#not-carried), [skill-plugin/migration.md](../skill-plugin/migration.md#archived), [구현 준비 점검](../readiness-2026-10-12.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "요약"은 찾아보기 편하도록 붙인 것이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

사용자는 설계(`skill-plugin/`)와 인터뷰 기록으로 의도한 skill을 만들 수 있는지 물었다. 구현에 필요한 것이 전부 정해졌는지 확인하고, 남은 것을 하나씩 물어 달라는 요청이었다. 점검 결과를 먼저 알리고 첫 질문으로 이것을 물었다. 점검 결과 전체는 [readiness-2026-10-12.md](../readiness-2026-10-12.md)에 있다.

### 먼저 알린 점검 결과

- 뼈대는 된다.
  - Q01~Q16 답과 원래 구상 0~12번은 모두 설계에 들어 있다.
  - 실행기의 바탕 코드(`step2step`, unit loop)도 있어서 spike를 시작할 수 있다.
- 예전 계획에서 직접 정한 결정 가운데 일부가 스킬 형태에도 맞는데 묻지 않은 채 빠졌다.
  - 가장 큰 것은 여러 저장소 프로젝트, 와이어프레임과 UI 디자인, 비개발자 지원, 개인 CLI 설정 분리다.
- 새로 정할 것은 3개다.
  - 같은 프로젝트에 새 요청이 왔을 때의 처리
  - 스택 확정을 받을 "새 기술"의 범위
  - 관리자 권한과 자격증명을 받는 방법
- AI가 채울 빈 곳 18개, 대안이 없는 spike 항목 9개, 문서 오류 7개는 판단을 받을 필요가 없어 질문하지 않았다.

### 왜 지금 묻는지

뒤의 질문들은 이 범위를 전제로 한다. 예를 들어 비개발자를 지원한다면 Q20에서 "터미널로 입력"은 선택지가 되기 어렵다.

### 무엇을 정하는지

아래는 모두 사용자가 [예전 계획](../../archive/app-plan/decisions.csv)에서 직접 정한 결정이다. Q01~Q16 답과 부딪히지 않는다. 지금 설계는 이 결정들을 아예 다루지 않거나, 근거가 약한 이유로 "이어받지 않음"에 넣었다.
- Q-009(작업 취소)는 Q10-2의 C안을 취소 기능으로 잘못 읽고 뺐다. C안은 중지 방식의 선택지였다.
- D-007(프로젝트 간 선호 공유)은 Q07을 근거로 뺐다. 하지만 Q07은 프로젝트 기억을 어디에 둘지를 물은 것이었다.

**큰 것 (구조가 바뀐다)**
1. **여러 저장소** ([Q-014](../../archive/app-plan/archive/2026-09-18-follow-up/014-project-repository-scope.md), [Q-015](../../archive/app-plan/archive/2026-09-18-follow-up/015-shared-project-documentation.md)): 처음 버전부터 한 프로젝트에 레포 여러 개를 연결한다. 상위 폴더 아래 기능별 레포를 두고, 공통 기획 레포 하나에 `.barrel/`을 둔다.
2. **와이어프레임과 UI 디자인** ([Q-010](../../archive/app-plan/archive/2026-09-18-follow-up/010-ui-design-confirmation.md), [Q-011](../../archive/app-plan/archive/2026-09-18-follow-up/011-wireframe-design-approval-flow.md), [Q-019](../../archive/app-plan/archive/2026-09-18-follow-up/019-image-generation-fallback.md)):
   - 화면이 있는 프로젝트는 기능명세 다음에 와이어프레임을 만들어 S5 의도 검토에 함께 올린다.
   - 상세 디자인은 S6 스택 확정에 함께 올린다.
   - 이미지는 어느 생성 서비스든 쓰고, 모던 레퍼런스를 참고해 AI Slop을 피한다.
3. **비개발자 지원** (D-001, [Q-001](../../archive/app-plan/archive/2026-09-18-follow-up/001-git-delivery.md), [Q-018](../../archive/app-plan/archive/2026-09-18-follow-up/018-nondeveloper-existing-project-start.md)): 첫 설정에서 사용자 정보를 받는다. 비개발자에게는 git 지식과 쓰던 정책부터 묻고, 없다고 하면 git은 Barrel이 맡아 병합까지 한다.
4. **프로젝트 간 공통 기억** (D-007, D-030, D-008): 밝힌 선호와 검증된 성공 경험을 여러 프로젝트에서 함께 쓴다. 이 Mac의 `~/.barrel/`에 두고(위치는 AI 제안), 프로젝트의 결정이 우선한다.
5. **개인 CLI 설정 분리** (D-048): 계정 로그인은 Q12대로 모두 쓴다. 다만 개인 지침, 메모리, MCP, 스킬, 훅은 목록에서 고른 것만 Barrel 세션에 가져온다.

**중간 것**

6. 검토 승인은 판(revision) 번호가 적힌 버튼으로만 받는다. 스레드 답글은 승인으로 치지 않는다 (D-045).
7. Slack에서 실행을 취소할 수 있다. 아직 반영하지 않은 변경은 보관할지 버릴지 고른다 ([Q-009](../../archive/app-plan/archive/2026-09-18-follow-up/009-cancelled-work-artifacts.md)).
8. CLI 업데이트로 드라이버가 깨지면, 검증된 공식 CLI를 따로 두고 쓴다 (D-049).
9. 구독 밖의 유료 사용은 허락 없이 하지 않는다 (D-012).
10. 기술 선택에 필요한 최소한의 실험은 별도 공간에서 한다 (D-042).
11. `.barrel/`을 직접 고치면 충돌을 검토하고, 해결안은 물어본 뒤 적용한다 (D-020).
12. 사내 소규모·테스터용으로 비공개 레포를 플러그인 마켓플레이스로 쓰고, 새 버전은 동의를 받아 올린다 (D-051, D-058).

**작은 것**

13. 다음 네 가지와 그 밖의 작은 결정들:
    - 화면을 직접 조작할 때는 쓸 시간대를 받는다 (D-025)
    - Slack에서도 절전 설정을 바꿀 수 있다 (D-047)
    - 연쇄 변경의 기본 처리 방식을 설정할 수 있다 (D-031)
    - macOS 15 이상, Apple Silicon을 지원한다 (D-054)

### 조사

직접 정한 결정을 되살릴지 묻는 질문이라 다른 서비스는 조사하지 않았다. 대신 각 결정의 답변 원문([archive/2026-09-18-follow-up/](../../archive/app-plan/archive/2026-09-18-follow-up/README.md))을 지금 설계와 대조했다.

### 선택지

- **모두 되살린다 (추천)** 1~13번을 스킬 구조에 맞춰 설계에 다시 넣는다. Q18~Q20은 이것을 전제로 묻는다.
- **큰 것만 하나씩 묻는다** 6~13번은 되살리고, 1~5번은 각각 따로 질문해서 정한다.
- **되살리지 않는다** 지금 설계대로 간다. 1~13번은 '이어받지 않은 결정' 목록에 이유와 함께 적는다.

추천 이유: 직접 정한 결정이고 인터뷰 답과 부딪히지 않는다. 특히 1~3번은 지금 진행하는 프로젝트의 레포 구조와 결과물 품질에 바로 영향을 준다. 대신 spike 범위가 커진다. 여러 저장소 과제와 와이어프레임 단계가 들어간다.

### 인터뷰 답과 함께 읽는 법

- **1번과 Q07·Q15:** Q07과 Q15의 "대상 레포"는 여러 저장소 프로젝트에서 공통 기획 레포로 읽는다(Q-015).
- **5번과 Q12:** Q12의 "config 폴더 … 다 활용하라고"는 그 폴더의 계정(로그인)을 모두 쓰라는 뜻으로 읽는다. 개인 설정은 D-048대로 고른 것만 가져온다.
- **4번과 Q07:** Q07은 프로젝트 기억을 레포에 두기로 했다. 프로젝트 지식은 계속 레포에 두고, 이 Mac에는 사람의 선호와 일반 노하우만 둔다.
- **4번의 저장 위치:** `~/.barrel/`은 AI가 제안했다. 사용자가 이의를 말하지 않았으므로 이 문장은 AI의 기록이다.
