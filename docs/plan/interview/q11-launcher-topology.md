# Q11. 실행기를 PC에 하나만 두는가, 프로젝트마다 두는가

- 질문일: 2026-10-07
- 관련: [session-context.md](../session-context.md)의 "아직 묻지 않은 질문"(Launcher topology), [q10-confirmed.md](q10-confirmed.md) 9절, [Q03-3](q03-3-launcher-and-slack.md), [Q04-2](q04-2-orchestrator-on-both-cli.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "요약"은 찾아보기 편하도록 붙인 것이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

skill-plugin 초안을 새 정본으로 다시 쓰는 작업을 시작하면서 물었다. 같은 메시지에 [Q12](q12-model-config-and-cli-fallback.md)와 한국어판 여부(작업 방식 질문, 이 기록에서는 생략)를 함께 물었다.

### 왜 지금 묻는지

Slack 문서를 다시 확인해 보니, 한 Slack 앱이 Socket Mode 연결을 여러 개 열면(최대 10개) 이벤트는 그중 아무 연결로나 간다. 문서 원문은 "each payload may be sent to _any_ of the connections"다. 프로젝트마다 실행기가 연결을 따로 열면 A 프로젝트 질문의 답이 B 프로젝트 실행기로 갈 수 있다. 이 답에 따라 실행기 문서의 프로세스 구조, 실행기 명령, 재시작 방식이 달라진다.

### 조사 요약

- Claude Code 백그라운드 세션은 사용자마다 감독 프로세스 하나가 모든 백그라운드 세션을 돌리고, 세션마다 프로세스를 따로 둔다(`claude daemon status`). ([agent view](https://code.claude.com/docs/en/agent-view))
- Slack Socket Mode의 연결은 앱마다 최대 10개이고, 이벤트는 아무 연결로나 간다. 그래서 인스턴스를 여러 개 띄우면 어느 인스턴스든 모든 이벤트를 처리할 수 있어야 한다. ([Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/))
- Slack Python SDK에는 외부 패키지 없이 도는 Socket Mode 클라이언트가 있어서, 어느 쪽이든 실행기를 가볍게 만들 수 있다. ([Python SDK](https://docs.slack.dev/tools/python-slack-sdk/socket-mode/))

### 선택지

- **PC에 하나 (추천)**
  - 실행기 프로세스 하나가 이 PC의 모든 프로젝트 실행을 맡고, Slack 연결도 하나만 연다.
  - 분리 실행이 안 되면 launchd 사용자 에이전트로 띄운다.
  - 실행기가 죽으면 모든 프로젝트가 멈췄다가 파일에서 이어 간다.
  - 화면으로 함께 보낸 정리:
    - 이벤트가 엇갈리지 않는다.
    - Barrel.app과 "화면"이 목록 하나를 읽는다.
    - 같은 계정의 한도를 한 곳에서 조절한다.
    - 실행기 장애가 모든 프로젝트에 미친다.
- **프로젝트마다 하나**
  - 프로젝트 실행마다 실행기를 따로 띄운다. 서로 영향이 없고, 실행이 끝나면 실행기도 끝난다.
  - 대신 Slack 이벤트가 다른 실행기로 갈 수 있어서, 받은 실행기가 주인 실행기에게 넘기는 장치가 필요하다.
  - 주인 실행기가 꺼져 있으면 그 채널의 "재개"를 받을 곳이 없다.

추천 이유:
- Slack 연결이 하나라 이벤트가 엇갈리지 않는다.
- Barrel.app과 "화면" 명령이 한 곳에서 프로젝트 목록을 읽는다.
- 여러 프로젝트가 같은 계정을 쓸 때 한도도 한 곳에서 조절한다.
- 대신 실행기가 죽으면 모든 프로젝트가 멈췄다가, 다시 뜬 실행기가 파일을 읽고 이어 간다. Q10-2의 재개와 같은 방식이다.

## 사용자 답변 (2026-10-07, 원문 그대로)

선택지를 골랐다.

```text
PC에 하나 (추천)
```

## 요약 (원문이 우선)

- 실행기는 PC에 하나만 둔다. 이 실행기가 그 PC에서 도는 모든 프로젝트 실행과 Slack 연결 하나를 맡는다.
- 분리 실행으로 띄우고, 분리 실행이 살아남지 못하면 launchd 사용자 에이전트로 띄운다. 고른 선택지에 적힌 내용이다.

## 이 답에 따른 정리 (AI 분석, 원문이 우선)

- [q10-confirmed.md](q10-confirmed.md) 9절에 미결로 남았던 "실행기를 프로젝트마다 하나 둘지, PC에 하나만 둘지"가 정해졌다.
- PC 화면은 Q10-2대로 프로젝트마다 포트와 토큰을 따로 둔다. Barrel.app은 이 실행기가 관리하는 프로젝트 목록을 읽는다.
- 실행기가 다시 뜨면 Q10 기본값 4번대로 재시작했다고 알린다. 사용자가 멈추지 않은 실행은 파일에서 이어 간다.
  - 이 자동 재개는 예전 계획의 Q-007(충돌이나 OS 재시작 뒤에는 확인을 거쳐 자동으로 이어 가고, 사용자가 멈춘 실행은 그대로 둔다)을 따른 AI 기본값이다.
  - 사용자가 따로 정하지 않았으므로 [open-decisions.md](../skill-plugin/open-decisions.md)에 검토 대상으로 적었다.
