# Q05. 구독 계정을 어떻게 나눠 쓰는가

- 질문일: 2026-10-06
- 관련: [어긋나는 점 5번](../README.md#conflicts), [원래 구상](../00-original-flow.md) 1번
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "요약"은 찾아보기 편하도록 붙인 것이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (요지)

원래 구상 1번은 계정명을 입력받아 Claude는 confdir, Codex는 `CODEX_HOME`으로 폴더를 나눠 구독을 최대한 활용한다고 했다. [Q04-2](q04-2-orchestrator-on-both-cli.md)에서 두 CLI의 세션을 같은 실행기로 띄우기로 했으므로, 실행기가 어느 계정으로 세션을 띄울지 정해야 했다.

함께 제시한 기술 사실:
- **Claude Code:** `CLAUDE_CONFIG_DIR`를 계정마다 다른 폴더로 지정하면 설정과 로그인이 분리된다. 플러그인과 skill도 이 폴더에 저장되므로, 계정 폴더마다 플러그인을 설치해야 한다.
- **Codex:** `CODEX_HOME`을 계정마다 다르게 지정하면 로그인 정보(`auth.json`)까지 분리된다.
- **이 레포의 실행기:**
  - Claude 실행기는 자식 세션에서 `CLAUDE*` 변수를 모두 지운다(`step2step/claude/runner.py:154-163`). 그래서 지금은 `CLAUDE_CONFIG_DIR`가 전달되지 않는다.
  - Codex 실행기는 `CODEX_HOME`을 그대로 넘긴다(`step2step/codex/transport.py:56-62`).
- **공통 기억:** 맥락은 계정이 아니라 프로젝트 문서에 두므로, 계정을 나눠도 맥락은 갈라지지 않는다.

선택지:
- **A** 계정 폴더를 지원하되 계정은 프로젝트별로 고정한다. 한도에 걸리면 리셋을 기다린다.
- **B** A에 더해, 계정을 쓸 수 없게 되면 같은 CLI의 다른 계정으로 자동 전환한다.
- **C** 계정을 나누지 않고, 각 CLI에 로그인된 계정 하나만 쓴다.

## 사용자 답변 (2026-10-06, 원문 그대로)

```text
이미 여러 계정에 대한 정보가 PC 에 등록되어있다면 그걸 활용해서 작업해주면 돼. 안되어있으면 그렇게 설정까지 하고. 내가 시킨대로 좀 해 토달지말고.
1번째 계정을 못쓰게 되면 2번째 계정을 사용하는건 전혀 문제가 없어. 관련된 경고 사항은 절대 문서나 코드에 넣지마.
```

## 요약 (원문이 우선)

- PC에 여러 계정 정보가 이미 등록돼 있으면 그것을 찾아서 쓴다. 등록돼 있지 않으면 계정별 설정(Claude `CLAUDE_CONFIG_DIR`, Codex `CODEX_HOME`)까지 해 준다.
- 1번째 계정을 쓸 수 없게 되면 2번째 계정을 쓴다(선택지 B에 해당).
- 이와 관련된 경고 사항은 문서나 코드에 넣지 않는다.
