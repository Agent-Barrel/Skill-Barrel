# Q07. 공통 기억을 어디에, 어떤 형태로 두는가

- 질문일: 2026-10-06
- 관련: [어긋나는 점 7번](../README.md#conflicts), [원래 구상](../00-original-flow.md) 1번, [insight.md](../insight.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "선택지 대응"은 찾아보기 편하도록 붙인 요약이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

### 왜 지금 묻는지

원래 구상 1번과 insight.md에서 이미 정한 것:
- 기억은 CLI 메모리나 특정 계정·세션에 의존하지 않고, 모든 세션이 참조한다.
- 기억은 최소 단위 맥락으로 나누고, 단위끼리 서로 참조하게 한다.
- 계획 초안 → 필요한 맥락을 읽고 수정 → 참조를 따라가며 다시 수정, 이 과정을 반복한다.
- 작업 세션에는 그 작업에 필요한 맥락만 준다.

남은 것은 기억을 어디에, 어떤 형태로 두는지다. [Q03-3](q03-3-launcher-and-slack.md)과 [Q04-2](q04-2-orchestrator-on-both-cli.md)에 따라 오케스트레이터와 작업 세션이 계속 새 세션으로 교체되므로, 이 결정이 모든 세션이 읽는 기반이 된다.

### 다른 서비스 조사 요약

- **Claude Code 자동 메모리:**
  - 기억 하나를 파일 하나에 두고 `MEMORY.md` 색인에 한 줄씩 적는다. 색인은 매 세션 처음 200줄까지 읽어 들인다.
  - 이 메모리는 PC마다, 설정 폴더(계정)마다 따로 저장되고, 백그라운드 세션이나 다른 세션이 띄운 세션에서는 꺼진다. 그래서 CLI 메모리에 기대지 않는다는 원래 구상 1번의 근거가 된다.
  - ([문서](https://code.claude.com/docs/en/memory))
- **Anthropic 맥락 설계 가이드:** 파일 경로 같은 가벼운 참조만 들고 있다가 필요할 때 읽으라고 권한다("just in time", "progressive disclosure"). ([글](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents))
- **Cline Memory Bank:** 레포 안에 고정 파일 6개를 두고, 작업마다 처음에 전부 읽는다. ([문서](https://docs.cline.bot/best-practices/memory-bank))
- **BMAD:** 큰 문서를 에픽 단위로 쪼개 두고, 구현 단위(스토리) 파일 하나에 그 작업에 필요한 맥락을 모아 준다(약 8천 토큰).
- **Kiro:** 작업마다 관련 요구사항 번호를 달아 거꾸로 추적할 수 있게 한다.

### 정할 것과 선택지

**7-a. 기억을 어디에 두는가**
- **A (추천)** 대상 프로젝트 레포 안에 두고 git으로 추적한다. 모든 계정, 두 CLI, 다른 PC가 같은 기억을 보고, 코드 이력과 함께 남는다. 실행 상태(세션 기록, 잠금 파일 등)는 레포 밖에 둔다.
- **B** 레포 밖 PC 공용 폴더(예: `~/.barrel/projects/<id>/`)에 둔다. 레포는 깨끗하지만, 다른 PC나 다른 사람과 공유되지 않고 코드 이력과도 따로 남는다.

**7-b. 어떤 형태로 나누는가**
- **X (추천)** 단위마다 파일 하나에 색인을 둔다.
  - 결정, 요구사항, 기능, 제약 하나를 파일 하나에 쓴다. 파일 머리에는 ID, 종류, 한 줄 요약, 관련 ID를 둔다.
  - 종류별 색인 파일에 단위마다 한 줄씩 적는다.
  - 인터뷰 답변 원문도 단위로 남기고, 결정이 그 원문을 가리키게 한다(이 인터뷰 기록 방식과 같다).
  - 작업 세션에는 그 작업이 참조한 단위 파일만 준다.
- **Y** 종류별 표(CSV)에 한 행씩 둔다(이전 `docs/plan` 방식). 파일 수는 적지만, 한 단위만 필요해도 표 전체를 열게 된다.

**반복을 멈추는 기준**(따로 정하지 않으면 이대로 하겠다고 제시함)
- 마지막 한 번의 읽기에서 계획이 바뀌지 않았다.
- 읽은 단위의 참조를 모두 읽었거나, 색인의 한 줄 요약을 보고 관련 없다고 판단했다.
- 두 조건을 모두 만족하면 멈춘다. 어떤 단위를 읽었는지는 작업 계약에 남기고, 작업 세션에는 그 목록의 단위만 넘긴다.

## 선택지 대응 (요약, 원문이 우선)

- 7-a: **A.** 대상 프로젝트 레포 안에 두고 git으로 추적한다. 실행 상태는 레포 밖에 둔다.
- 7-b: **X.** 단위마다 파일 하나에 색인을 두고, ID로 서로 참조한다.
- 반복을 멈추는 기준에 대해 사용자는 따로 이의를 말하지 않았다. 이 문장은 AI의 기록이다.
