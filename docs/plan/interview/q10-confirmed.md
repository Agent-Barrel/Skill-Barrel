## 2. Slack 진행 보고

### 2.1 무엇을 어디에 보내는가

- 기존 메시지를 고치지 않고, 새 메시지로 계속 보낸다. [Q10 답]
- 프로젝트마다 채널 하나, 질문마다 스레드 하나를 쓴다. Q09-a를 그대로 따른다.
- 채널 본문(새 메시지)에 보내는 것: [Q10 답: 10-a A]
  - 단계 전환
  - 대주제와 중주제의 시작과 완료
  - 질문, 사람만 할 수 있는 일 요청
  - 재시도 끝에 포기한 작업
  - 사용 한도로 전체가 멈춤, 그리고 재개
  - 전체 완료
  - 상태 요약(2.4), 중지됨과 재개됨(3장) [기본값]
- 스레드에 다는 것: [Q10 답: 10-a A]
  - 말단 작업의 시작, 계획 승인, 완료, 재시도는 그 작업이 속한 중주제 시작 메시지의 스레드에 단다.
  - 인터뷰 단계의 세부(조사 시작과 끝 등)는 그 단계 시작 메시지의 스레드에 단다.

### 2.2 알림 [기본값]

- 멘션은 사람이 해야 할 일에만 한다. 질문, 검토 요청, 로그인이나 자격증명처럼 사람만 할 수 있는 일, 전체 완료가 여기에 든다.
- 보고마다 푸시를 받고 싶으면 사용자가 채널 알림을 "모든 새 게시물"로 바꾼다. 봇은 이 설정을 바꿀 수 없다.
- 모든 메시지의 `text`에 요약을 넣는다. 휴대폰 알림은 `text`만 보여 준다.
- 채널 본문 메시지 끝에는 "말단 34/80 완료 · 진행 3 · 막힘 1 · 답 대기 1" 같은 진행 한 줄을 붙인다. 그러면 마지막 메시지가 곧 현재 상태가 된다.

### 2.3 보내는 규칙 [기본값]

- 상태가 바뀔 때만 보낸다. 재시도 중인 오류는 결과가 나올 때까지 보내지 않는다.
- 1분 안에 몰린 스레드 세부 이벤트는 한 메시지로 묶는다.
- 채널당 초당 1건을 넘기지 않는다.
- 실행기가 다시 뜨면 재시작했다고 알린다.

### 2.4 상태 요약(스냅샷) [Q10 답: 10-b X]

- 새 메시지로 보낸다. 보내는 때는 다음과 같다.
  - 사용자가 채널에 "상태"라고 쓰거나 봇을 멘션할 때
  - 단계가 바뀌거나 대주제가 끝날 때
  - 작업 중인데 채널 본문이 3시간 동안 조용할 때. 살아 있다는 신호를 겸한다.
- 내용:
  - 대주제와 중주제 트리, 각각의 상태
  - 실행 중인 세션(CLI, 모델)
  - 막힌 작업과 그 이유
  - 답을 기다리는 질문(스레드 링크)
- 상태 요약 메시지에 [작업 중지] 버튼을 단다(3장). [기본값]

### 2.5 질문

- 질문 글은 `[{프로젝트명}-질문]`으로 시작하고, 스레드로 답해 달라는 말을 함께 넣는다. [Q10 답]
  - 안내 문장은 "이 스레드에 답해 주세요"다. 프로젝트명은 실행을 시작할 때 정한 이름이고, 기본값은 레포 폴더 이름이다. [기본값]
- 답이 없는데 반드시 답이 필요한 질문은 질문 후 1시간, 2시간, 4시간, 8시간 뒤에 한 번씩 멘션한다. 그 뒤로는 8시간마다 보낸다. [Q10 답]
  - 다시 알림은 그 질문의 스레드에 답글로 달고 사용자를 멘션한다. [기본값]
  - 시간은 질문이 실제로 Slack에 올라간 때부터 잰다. [기본값]
  - "반드시 답이 필요한 질문"은 막힌 작업을 풀어야 하는 질문과 요청 전부로 본다. Q01과 Q06에 따라 Barrel은 AI가 판단할 수 없는 것만 묻기 때문이다. [기본값]
  - 작업이 중지된 동안에는 다시 알림을 멈춘다(3장). [Q10-2 답: 10-d A]
- 질문 스레드의 답글은 그 질문의 답으로 받는다. [기본값]

### 2.6 채널 명령과 지시

- 채널에 아래 낱말만 쓰면 명령으로 받는다.

  | 낱말 | 하는 일 | 출처 |
  | --- | --- | --- |
  | "상태" (또는 봇 멘션) | 상태 요약을 보낸다 | [Q10 답: 10-b X] |
  | "중지" | 확인 없이 바로 작업을 중지한다 | [기본값] |
  | "재개" | 중지한 작업을 재개한다 | [Q10-2 답: 10-d A] |
  | "언어 영어", "language korean" 등 | Slack 언어를 바꾼다 | [기본값] |
  | "화면" | 이 Mac에서 PC 화면을 연다 | [AI] |

  영어 설정에서는 status, stop, resume, view도 같은 뜻으로 받는다. [AI]
- 그 밖의 채널 글과 보고 스레드의 답글은 오케스트레이터에 지시로 넣는다. [기본값]
- 지시가 처음 정한 내용을 바꾸는 것이면, Q01대로 연쇄 변경까지 함께 묻는다. [기본값]

### 2.7 언어

- Slack에 보내는 언어는 한국어와 영어 중에서 고른다. 기본은 한국어이고, 한 번 정하면 바꿀 때까지 그 언어로 보낸다. [Q10 답]
- 설정은 하나로 두고 모든 프로젝트에 쓴다. 채널에 "언어 영어"나 "language korean"이라고 쓰면 바뀌고, 그다음 메시지부터 바뀐 언어로 간다. PC 화면도 같은 언어를 따른다. [기본값]
- **한국어일 때:** [Q10 답: 10-c K]
  - 진행 보고는 실행기의 한국어 고정 문형에 값만 채워 보낸다. 고정 문형은 개발할 때 영어 원문으로 쓰고, Skill-Techblog로 한 번 한국어로 만든다.
  - 작업 이름은 작업을 나눌 때 한국어 표시 이름을 함께 만든다. 대주제와 중주제는 구현 전 검토 문서를 만들 때, 소주제는 그 중주제를 나눌 때 묶어서 만든다.
  - 매번 내용이 달라지는 글(질문, 검토 문서, 최종 보고)은 Q08대로 Skill-Techblog로 쓴다. 진행 보고에는 그 글로 가는 링크만 단다.
- **영어일 때:** [기본값]
  - 고정 문형의 영어 원문과 영어 정본(질문, 검토 문서, 최종 보고, 작업 이름)을 그대로 보낸다. Skill-Techblog를 거치지 않는다.
  - 질문 머리말은 `[{프로젝트명}-Question]`이다.
  - 한국어로 다시 바꾸면, 한국어 표시 이름이 아직 없는 작업은 그때 묶어서 만든다.

### 2.8 권한과 내용 [기본값]

- 채널은 비공개로 만든다.
- 답, 지시, 명령, 버튼은 등록한 사용자 본인 계정에서 온 것만 받는다. 예전 계획 D-043과 같은 원칙이다.
- 자격증명, 토큰, 키는 보내기 전에 가린다.
- 긴 내용은 레포 문서 경로나 커밋·PR 링크로 대신한다.
- PC 화면 주소는 토큰이 들어 있으므로 Slack에 보내지 않는다. [Q10-2 답: 10-e W]

### 2.9 Slack이 끊겼을 때

- 연결이 복구될 때까지 기다린다. 복구되면 현황(상태 요약)만 보내고, 쌓아 둔 질문을 한꺼번에 보낸다. 끊긴 동안의 작업 내역은 보내지 않는다. [Q10 답]
- 작업은 계속한다. 기다리는 것은 보내기뿐이다. 보내지 못한 질문에 걸린 작업은 Q01대로 그 작업만 멈춘다. [기본값]
- macOS 알림과 터미널 상태 명령은 두지 않는다. 대신 PC 화면에 Slack 연결 상태와 아직 보내지 못한 질문 수를 보여 준다. [기본값]

## 3. 작업 중지와 재개 [Q10-2 답: 10-d A]

- **어디서 멈추나:** PC 화면에서도, Slack에서도 멈출 수 있다. [Q10 답]
- **범위:** 그 프로젝트의 실행 전체(오케스트레이터와 모든 작업 세션)를 멈춘다. 작업 하나만 멈추는 기능은 없다.
- **순서:**
  1. 새 세션을 띄우지 않는다. 중지된 상태에서는 실행기가 세션을 다시 띄우지 않는다.
  2. 진행 중인 턴을 모두 끊는다.
     - Claude: ESC (`step2step/claude/session.py:511`)
     - Codex: `turn/interrupt` (`step2step/codex/session.py:441`), 백그라운드 터미널 정리(`:575`)
  3. 세션을 닫는다. 15초 안에 멈추지 않는 세션은 프로세스를 끝낸다(`stop(force=True)`, `step2step/claude/session.py:186`).
  4. 실행 상태에 "중지됨"과 끊긴 작업을 기록하고, Slack과 PC 화면에 알린다.
- **파일 변경:** 되돌리지 않는다. 재개하면 끊긴 말단 작업을 새 세션이 남은 변경 위에서 다시 맡는다.
- **중지된 동안:** 질문 다시 알림과 3시간 상태 요약을 멈춘다. 그 사이에 온 답은 기록해 두었다가 재개할 때 반영한다.
- **재개:** 새 오케스트레이터가 기억 단위와 실행 상태를 읽고 이어 간다.
- **멈추고 재개하는 방법:**

  | 어디서 | 중지 | 재개 | 출처 |
  | --- | --- | --- | --- |
  | Slack 버튼 | 상태 요약 메시지의 [작업 중지]. Slack 확인 창이 한 번 뜬다 | "중지됨" 메시지의 [재개] | 중지는 [기본값], 재개는 [Q10-2 답: 10-d A] |
  | Slack 낱말 | "중지". 확인 없이 바로 멈춘다 | "재개" | 중지는 [기본값], 재개는 [Q10-2 답: 10-d A] |
  | PC 화면 | [중지]. 한 번 확인을 받는다 | [재개] | [Q10-2 답], 확인은 [AI] |

- **권한:** 중지와 재개는 등록한 사용자 본인만 할 수 있다. [기본값]

## 4. PC 화면 [Q10-2 답: 10-e W]

- **목표:** 작업 내용을 이 PC에서 시각적으로 본다. 굉장히 가볍게 동작해야 한다. [Q10 답]
- **구성:** 실행기가 띄우는 로컬 웹 페이지 하나다.
  - Python 표준 라이브러리 서버와 SSE로 실시간 갱신한다.
  - 외부 패키지와 Node 빌드는 없다.
  - 페이지 크기는 약 6 KB(스타일 포함 약 15 KB)다.
- **측정값:** 이 Mac에서 2026-10-07에, 실행기와 비슷한 프로세스로 쟀다.
  - 메모리 +1.2~2.4 MiB
  - 대기 중 CPU 1 ms 미만, 분당 4회 깨어남
  - 브라우저 탭 자체의 메모리는 재지 않았다.
- **보여 주는 것:**
  - 대주제 > 중주제 > 말단 트리와 상태
  - 실행 중인 세션(CLI, 모델)
  - 막힌 작업과 그 이유
  - 답을 기다리는 질문(Slack 스레드 링크)
  - 최근 이벤트
  - Slack 연결 상태와 아직 보내지 못한 질문 수
- **쓰기 동작:** [중지]와 [재개]뿐이다. 질문에 답하거나 지시를 보내는 일은 Slack에서 한다.
- **보안:**
  - 127.0.0.1에서만 연다.
  - 요청마다 토큰, Host, Origin을 확인하고, POST만 받는다.
    > **이후 정리(2026-10-11, AI):** 페이지는 POST로 열 수 없다. 그래서 "POST만 받는다"는 중지와 재개 요청에 적용한다. 페이지와 실시간 갱신(SSE)은 부작용 없는 GET으로 열고, 토큰과 Host를 확인한다. 브라우저는 같은 출처의 GET 요청에는 Origin을 보내지 않으므로, Origin 확인도 중지와 재개에만 한다. [pc-view.md](../skill-plugin/pc-view.md#security)를 본다.
  - 중지와 재개는 인자를 받지 않는다.
  - 에이전트가 쓴 글자는 HTML로 해석되지 않게 처리한다.
  - 그래서 위조 요청으로 할 수 있는 최악은 작업을 멈추는 것이다. 코드 실행으로 이어지지 않는다.
- **언어:** Slack 언어 설정을 따른다. [기본값]

### 4.1 닫은 화면을 다시 여는 방법 [AI]

사용자가 방법을 강구하라고 맡겼다([Q10-2 답](q10-2-pc-view-stop-language.md)). 원칙은 두 가지다. 상주 프로세스를 늘리지 않고, 토큰이 든 주소를 Slack으로 내보내지 않는다.

1. **주소를 고정한다.** 프로젝트마다 포트와 토큰을 한 번 정해, 본인만 읽을 수 있는 파일로 실행 상태 폴더에 둔다. 실행기가 다시 떠도 주소가 같으므로 브라우저 방문 기록이나 즐겨찾기로 다시 열 수 있다. 처음 실행을 시작할 때는 기본 브라우저로 화면을 열어 준다.
2. **Spotlight나 Dock에서 "Barrel"로 연다.**
   - skill이 처음 설정할 때 `~/Applications/Barrel.app`을 만든다. macOS 기본 도구 `osacompile`로 만드는 AppleScript 앱이다.
   - 실행하면 지금 도는 프로젝트의 화면 주소를 읽어 기본 브라우저로 열고 바로 끝난다. 상주하지 않는다.
   - 도는 프로젝트가 여럿이면 목록에서 고르고, 하나도 없으면 그렇다고 알린다.
   - 앱 안에는 토큰을 넣지 않고, 열 때마다 파일에서 읽는다.
   - ⌘Space에서 "Barrel"을 치거나, Dock에 끌어 두고 누르면 된다.
   - 이 Mac(macOS 15.7.5)에서 시험했다. 만든 앱은 192 KB였고, ad-hoc 서명이 붙어 `codesign` 검증을 통과했다. 격리 속성이 없어 Gatekeeper 경고 없이 실행됐다.
3. **Slack 채널에 "화면"이라고 쓴다.** 실행기가 이 Mac에서 그 프로젝트의 화면을 연다. 휴대폰에서 써도 PC에 열린다.
4. **skill을 다시 부른다.** 이미 도는 프로젝트에서 skill을 부르면, 오케스트레이터를 새로 띄우지 않고 화면을 연다.

## 5. 보내는 경로와 기존 코드 [기본값]

- 봇으로 메시지를 보내는 것은 실행기뿐이다. 오케스트레이터와 작업 세션은 실행기 명령으로 이벤트를 남긴다.
- 공식 Slack MCP는 사용자 토큰으로 보내서 알림이 가지 않으므로, 보고에는 쓰지 않는다(Q09). 에이전트가 Slack 내용을 읽을 때만 쓴다.
- 지금 있는 코드를 레포 밖 실행 상태 폴더의 이벤트 기록 하나로 모은다. Slack 보내기, 상태 요약, PC 화면이 모두 이 기록을 읽는다.
  - `Notifier`(`barrel/core/unitloop.py:326`): 지금은 문제가 생겼을 때만 명령, 웹훅, macOS 알림으로 보낸다.
  - `RunState`(`barrel/core/unitloop.py:370`): 작업 단위의 시작·완료·막힘을 레포 밖 `state.json`에 적는다.
  - 세션 감시 이벤트(`step2step/claude/watchdog.py:17`): `died`, `usage_limited`, `dialog_waiting`, `silent`, `no_progress`, `recovered`
- 어느 일이 어느 스레드인지도 실행 상태에 저장한다. 실행기가 재시작해도 같은 스레드에 이어 쓴다.

## 6. 정본 [기본값]

Slack 메시지와 PC 화면은 정본이 아니다. 정본은 레포의 기억 단위와 실행 상태다(Q07). 그래서 Slack 무료 플랜의 90일 제한에 걸려도 잃는 것이 없다.

## 8. spike에서 확인할 것

1. **Socket Mode 수신:** 버튼 클릭(확인 창 포함), 채널 낱말 명령, 스레드 답글을 받고, 보낸 사람이 등록한 사용자인지 확인한다.
2. **알림:** 기본 알림 설정에서 멘션이 휴대폰 푸시로 오는지, 스레드 답글 속 멘션(다시 알림)도 오는지 확인한다.
3. **중지:** Claude와 Codex 세션이 15초 안에 모두 멈추는지, 멈춘 뒤 다시 띄워지지 않는지, Codex 백그라운드 프로세스가 남지 않는지 확인한다.
4. **재개:** 끊긴 말단 작업을 새 세션이 남은 변경 위에서 이어 맡는지 확인한다.
5. **Slack 끊김과 복구:** 복구 후 상태 요약 하나와 쌓인 질문만 가는지, 다시 알림 시간이 실제로 올라간 때부터 재지는지 확인한다.
6. **실행기 재시작:** 같은 스레드에 이어 쓰는지, PC 화면 주소가 그대로인지 확인한다.
7. **PC 화면:**
   - 실제 실행기에서 메모리와 CPU를 다시 잰다. 브라우저 탭의 메모리도 잰다.
   - Chrome과 Safari에서 열리는지 확인한다. Safari 26.4에서 "안전하지 않은 웹사이트 경고"를 켜 두면 localhost가 막히는 WebKit 버그가 있었다(2026-06-04 수정).
8. **Barrel.app:** `~/Applications`에 둔 앱이 Spotlight에서 찾아지는지, 다른 Mac과 다른 macOS 버전에서도 경고 없이 실행되는지 확인한다.
9. **워크스페이스 플랜:** 무료 플랜이면 이 봇도 앱 10개 제한에 들어간다. 메시지가 많을 때 `message_limit_exceeded`가 나는지 확인한다.
