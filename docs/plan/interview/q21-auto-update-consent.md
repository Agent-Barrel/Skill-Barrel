# Q21. 원격에서 자동 업데이트할 때 동의를 받는가

- 질문일: 2026-10-12
- 관련: [Q17-2](q17-2-repo-list-config-and-updates.md)의 8번, [Q17](q17-restore-archived-decisions.md)의 12번(예전 결정 D-058), [skill-plugin/launcher.md](../skill-plugin/launcher.md#versions), [구현 준비 점검](../readiness-2026-10-12.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "요약"은 찾아보기 편하도록 붙인 것이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

[Q17-2](q17-2-repo-list-config-and-updates.md)의 답을 기록한 뒤, 이전 이름을 지우는 범위와 같은 메시지에서 물었다.

### 왜 지금 묻는지

8번을 "검증된 CLI를 따로 두기"(D-049) 대신 "원격의 스킬로 자동 업데이트"로 바꿨다. 그런데 Q17에서 함께 되살린 12번(D-058)은 "새 버전은 동의를 받아 올린다"이다. 업데이트할 때 동의를 받을지 정해야 업데이트 기능을 만들 수 있다.

### 다른 도구 조사 요약

- **Claude Code 본체:** 백그라운드에서 스스로 업데이트한다. 끄려면 `DISABLE_AUTOUPDATER=1`을 설정한다. ([setup 문서](https://code.claude.com/docs/en/setup))
- **Claude Code 플러그인:** 마켓플레이스마다 자동 업데이트를 켜고 끈다. 켜 두면 설치한 플러그인이 백그라운드에서 바뀐다. ([플러그인 보안 문서](https://code.claude.com/docs/en/plugins/security))
- **VS Code:** 기본은 백그라운드에서 자동으로 확인한다. 시작할 때만 확인, 수동 확인, 끄기 중에서도 고를 수 있다. ([VS Code 문서](https://code.visualstudio.com/docs/enterprise/updates))
- **예전 계획(D-064):** Tauri updater로 버전마다 동의를 받기로 했다.

### 선택지

- **A (추천) 호환이 깨졌을 때만 바로 올리고, 나머지는 동의를 받아 올린다.**
  - 원격 레포의 새 버전을 정기적으로 확인한다.
  - CLI 업데이트로 Barrel이 동작하지 않게 되면, 그 CLI를 지원하는 새 버전을 동의 없이 바로 올린다. 올린 뒤 하던 작업을 파일에서 이어 가고, Slack에 알린다.
  - 그 밖의 새 버전은 12번대로 Slack 버튼으로 동의를 받고, 도는 작업이 없을 때 올린다.
- **B 항상 바로 올린다.** 동의 없이 도는 작업이 없을 때 올리고, 호환이 깨졌으면 즉시 올린다. Slack에는 알리기만 한다. Claude Code나 VS Code와 같은 방식이고, 12번의 동의는 빠진다.
- **C 항상 동의를 받는다.** 12번 그대로다. 호환이 깨져도 버튼을 누를 때까지 작업이 멈춰 있다.

추천 이유: 호환이 깨지면 작업은 이미 멈춘 상태다. 그때 동의를 기다리면 그만큼 더 멈춘다. 다른 업데이트는 12번의 동의를 남겨 두어, 테스터 PC에 예상하지 못한 버전이 깔리지 않게 한다.

질문 창에 보인 선택지 이름과 설명:
- `호환 깨지면 바로 (추천)`: CLI 업데이트로 Barrel이 동작하지 않으면 새 버전을 바로 올리고, 그 밖의 새 버전은 Slack 버튼으로 동의를 받아 도는 작업이 없을 때 올립니다.
- `항상 바로`: 동의 없이 도는 작업이 없을 때(호환이 깨졌으면 즉시) 올리고 Slack에 알리기만 합니다.
- `항상 동의 후`: 12번(D-058) 그대로입니다. 호환이 깨져도 동의 버튼을 누를 때까지 작업이 멈춰 있습니다.

## 사용자 답변 (2026-10-12, 원문 그대로)

선택지를 고르지 않고 직접 썼다.

```text
slack 에도 안알려도 돼. claude code 처럼 그냥 스킬도 실행할 때 최신버전이랑 자기 버전 맞는지 확인하고 업데이트하도록 하면 된다니까?
```

## 요약 (원문이 우선)

- 업데이트할 때 동의를 받지 않는다. Slack에도 알리지 않는다.
- Claude Code처럼, 스킬도 실행할 때 원격의 최신 버전과 자기 버전이 같은지 확인하고 업데이트한다.

## 이 답에 따른 정리 (AI 분석, 원문이 우선)

- **12번이 바뀐다:** Q17에서 되살린 12번(D-058)의 "동의를 받아 올린다"는 이 답으로 바뀐다. 업데이트에는 동의도 알림도 없다.
- **확인 시점(AI가 정한다):** 답의 "실행할 때"와 "claude code 처럼"을 따른다.
  - skill을 실행할 때
  - 실행기가 시작할 때
  - 실행기가 도는 동안 정기적으로. Claude Code도 실행 중에 백그라운드에서 확인한다.
  - CLI 업데이트 뒤 화면 읽기 보정이 실패했을 때([Q17-2](q17-2-repo-list-config-and-updates.md)의 8번이 생긴 이유)
- **올리는 것:** 모든 계정 폴더(Claude Code, Codex)의 Barrel 플러그인과 실행기(`barrel` 명령)를 함께 올린다. 둘의 버전이 어긋나지 않게 하려는 것이다.
- **적용 시점(AI가 정한다):**
  - 새 버전은 바로 받는다.
  - 실제 교체는 작업 중인 턴이 없는 지점에서 한다. 실행기가 다시 뜨면 세션은 파일에서 이어 간다(재개와 같은 경로).
- **기록:** Slack에는 아무것도 보내지 않는다. 실행기 로그와 이벤트 기록에만 남긴다. 이벤트 기록은 Slack으로 가지 않는 종류로 둔다.
- **원격 주소:** 원격은 플러그인 마켓플레이스인 GitHub 레포다. 레포를 다른 organization으로 옮기면 계정 폴더마다 등록한 마켓플레이스 주소도 새 주소로 고쳐야 한다. 업데이트 확인 기능이 이 일도 맡게 한다.
  > **이후 정리(2026-10-12):** 레포를 공개 레포 [Agent-Barrel/Skill-Barrel](https://github.com/Agent-Barrel/Skill-Barrel)로 옮겼다. 아직 설치한 곳이 없으므로 처음부터 이 주소를 쓴다.
- 아직 `skill-plugin/`에 반영하지 않았다.
