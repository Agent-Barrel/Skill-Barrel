# Q03-2. 오케스트레이터 교체를 자동으로: 최초 세션을 부트로더로

- 답변일: 2026-10-06
- 관련: [Q03](q03-orchestrator-restart.md)의 후속, [어긋나는 점 3번](../README.md#conflicts)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 내용이 다르면 답변 원문이 우선한다.

## 직전에 AI가 보고한 내용 (요약)

Q03의 A안을 skill로 구현할 수 있는지 검토한 결과를 보고했다. 전문은 [Q03 가능성 검토](q03-orchestrator-restart.md#가능성-검토-ai-분석-2026-10-06)에 있다.

- 인터뷰 단계: 가능하지만, 오케스트레이터를 교체할 때마다 사용자가 `/clear`를 한 번 입력해야 한다. 입력하면 `SessionStart` 훅이 인계 문서를 넣어 새 대화가 이어 간다. skill이 자기 대화를 스스로 비울 방법이 없기 때문이다.
- 구현 단계: 가능하다. 플러그인에 Python 드라이버를 넣어 사용자 세션과 분리된 프로세스로 띄운다.

## 사용자 답변 (2026-10-06, 원문 그대로)

같은 메시지에 질문 4의 답이 함께 있었다. 질문 4 부분은 [Q04](q04-target-cli.md)에도 기록했다.

```text
3번 질문에 대해, 너가 말한대로 교체할 때마다 "/clear"를 한 번 입력하면 자동으로 동작하는게 아니잖아. 세션이 새로운 세션으로 바뀌는건 자동으로 이뤄져야 해.
그렇게 하지말고, 오케스트레이션 세션도 최초에 skill 을 호출한 세션에서 호출하는 형태로 동작하게 하는게 가능할지 검토해줘. 최초에 스킬 호출하는 세션은 이 작업의 부트로더 같은 느낌으로만 작동하는거야. 이거 검토해줘.
그리고 질문 4는 A안으로 진행해줘.
```

## 요약 (원문이 우선)

- `/clear`를 사람이 입력하는 방식은 받아들이지 않는다. 세션 교체는 자동이어야 한다.
- 최초에 skill을 호출한 세션은 부트로더 역할만 한다. 오케스트레이션 세션도 이 세션에서 띄우는 구조가 가능한지 검토한다.

## 가능성 검토 (AI 분석, 2026-10-06)

> **사용자 의도와 다름:** 이 검토는 skill을 실행한 세션이 계속 살아서 질문을 중계한다고 잘못 이해한 채 썼다. 사용자는 그 세션이 오케스트레이터만 띄우고 끝나며, 질문은 Slack으로 한다고 정정했다. [Q03-3](q03-3-launcher-and-slack.md)을 본다.

이 절은 사용자 답변이 아니라 사용자가 요청한 검토의 결과다.

**결론: 가능하다.** Claude Code는 공식 기능으로 할 수 있고, Codex는 Stop 훅으로 대기하는 우회 방식으로 할 수 있다. 사람이 `/clear`를 입력할 필요가 없다.

### 구조

| 구성 | 하는 일 |
| --- | --- |
| 부트로더 세션 | 사용자가 skill을 호출한 세션이다. 하는 일은 세 가지뿐이다: 드라이버가 없으면 띄우기, 드라이버가 보낸 질문과 보고를 사용자에게 보여 주기, 사용자 답을 받은 그대로 파일에 적어 넘기기. 상태를 갖지 않는다. |
| 드라이버 | 부트로더가 띄우는 분리된 Python 프로세스다(unit loop + `step2step` 확장). 오케스트레이터 세션과 작업 세션을 띄운다. 단계나 주제가 끝나거나 맥락이 한도를 넘으면 오케스트레이터를 닫고, 문서 상태를 바탕으로 새 오케스트레이터를 띄운다. |
| 오케스트레이터 세션 | 인터뷰 단계와 구현 단계 모두 이 세션이 맡는다. 사람에게 물을 것은 질문 파일에 쓰고 턴을 끝낸다. 드라이버가 답을 받아 다음 프롬프트로 넣는다. |

이 구조에서 얻는 것:
- **교체가 사람 입력 없이 일어난다.** 드라이버가 기록 파일의 토큰 사용량과 단계 경계를 보고 교체한다. Claude는 `message.usage`, Codex는 `token_count`를 쓴다. 근거는 [Q03 가능성 검토](q03-orchestrator-restart.md#가능성-검토-ai-분석-2026-10-06)에 있다.
- **부트로더에서 자동 압축이 일어나도 잃는 것이 없다.** 부트로더에 쌓이는 것은 질문과 답의 텍스트뿐이고, 원본은 파일에 있다.
- **부트로더가 닫혀도 작업은 계속된다.** 다른 세션에서 skill을 다시 부르면 그 세션이 새 부트로더가 되어 진행 중인 드라이버에 다시 붙는다.

**부트로더가 오케스트레이터를 직접 띄우지 않고 드라이버를 거치는 이유:**
1. 부트로더가 닫혀도 진행이 계속돼야 한다([Q03](q03-orchestrator-restart.md) A안의 구현 단계 조건).
2. 교체 판단을 코드가 하므로 같은 상황에서 같은 결과가 나온다.
3. 같은 드라이버를 두 CLI에서 함께 쓸 수 있다([Q04](q04-target-cli.md)).

### 부트로더를 사람 입력 없이 깨우는 방법

질문이 오면 한가하던 부트로더가 스스로 새 턴을 시작해야 한다. 여기서 두 CLI가 갈린다.

- **Claude Code: 공식 기능으로 가능하다.**
  - 플러그인 모니터(`monitors/monitors.json`)는 "runs in the background for the whole session. What it prints reaches Claude as notifications". 대화형 세션에서만 켜진다.
  - Monitor 도구 문서에는 "Claude interjects when an event arrives"라고 되어 있다.
  - 드라이버의 이벤트 파일을 지켜보는 모니터를 플러그인에 넣으면, 질문이 왔을 때 부트로더가 새 턴을 시작한다.
  - 출처: [플러그인 모니터](https://code.claude.com/docs/en/plugins/components), [Monitor 도구](https://code.claude.com/docs/en/tools-reference)
- **Codex: 우회 방식으로 가능하다.**
  - 백그라운드 이벤트로 한가한 세션을 깨우는 기능은 아직 없다. 기능 요청 [#29922](https://github.com/openai/codex/issues/29922), [#32188](https://github.com/openai/codex/issues/32188), [#51272](https://github.com/openai/codex/issues/51272)가 열려 있고, [#29865](https://github.com/openai/codex/issues/29865)는 not planned로 닫혔다.
  - 대안은 Stop 훅이다. Stop 훅이 이벤트를 기다리다가(기본 timeout 600초), 이벤트가 오면 `decision: "block"`과 함께 그 이벤트를 reason으로 돌려준다. 공식 문서에 따르면 이렇게 하면 reason이 "a new user prompt"가 되어 턴이 이어진다.
  - 이벤트가 없으면 "계속 대기"로 이어 가므로, 기다리는 동안 약 10분마다 작은 모델 호출이 생긴다.
  - 사용자에게 보낸 질문의 답을 기다리는 동안에는 훅이 대기하지 않고 턴을 끝내서 사용자가 입력할 수 있게 한다.
  - 출처: [Codex 훅](https://learn.chatgpt.com/docs/hooks)

### 남는 제약

- Codex에서는 기다리는 동안 주기적인 모델 호출 비용이 든다. upstream에 깨우기 기능이 생기면 그쪽으로 바꾼다.
- Claude 플러그인 모니터는 드라이버가 띄운 오케스트레이터 세션과 작업 세션에서도 켜진다. 이 세션들도 대화형 Claude 세션이기 때문이다. 그래서 환경변수 같은 역할 표시를 두고, 부트로더에서만 동작하게 해야 한다.
- 드라이버는 Python 프로그램이라 사용자 PC에 Python 3.12 이상이 필요하다([Q03 검토](q03-orchestrator-restart.md#가능성-검토-ai-분석-2026-10-06)와 같다).

### spike에서 확인할 것

[Q03 검토](q03-orchestrator-restart.md#가능성-검토-ai-분석-2026-10-06)의 3번(Codex `/clear` 인계)은 이 구조에서 필요 없어져 뺐다.

1. macOS에서 부트로더 세션이 끝난 뒤에도 드라이버가 계속 도는지(Q03의 1번과 같다).
2. `step2step` 화면 보정이 현재 버전(Claude Code 2.1.291, codex-cli 0.155.1)에서 유효한지(Q03의 2번과 같다).
3. Claude 플러그인 모니터의 알림으로 한가한 부트로더가 새 턴을 시작하는지.
4. Codex Stop 훅 대기 방식: timeout 상한, 대기 중 사용자 입력 처리, 시간당 비용.
