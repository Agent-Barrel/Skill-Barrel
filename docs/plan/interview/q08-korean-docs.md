# Q08. 어떤 문서를 한국어로 두고, 무엇을 정본으로 삼는가

- 질문일: 2026-10-06
- 관련: [어긋나는 점 8번](../README.md#conflicts), [insight.md](../insight.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "선택지 대응"은 찾아보기 편하도록 붙인 요약이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

### 왜 지금 묻는지

insight.md에서 정한 것: LLM은 한국어로 쓰면 직역투가 자주 나오므로, 문서 초안은 영어로 쓰고 번역 지침을 준 별도 작업으로 번역한다. Skill-Techblog를 활용한다. 이 원칙은 그대로 따르고, 남은 것은 무엇을 한국어로 내보낼지와 영어·한국어 중 어느 쪽을 정본으로 둘지였다. [Q07](q07-shared-memory.md)에서 기억을 단위 파일로 레포에 두기로 했으므로 그 파일들의 언어를 정해야 했다.

### 조사 요약

- LLM이 영어가 아닌 언어로 쓴 글에는 영어식 어휘와 문법이 섞인다. ([arXiv 2608.17399](https://arxiv.org/html/2608.17399))
- 다국어 LLM은 다른 언어로 질문해도 내부 판단은 영어 중심으로 한다는 분석이 있다. 영어로 먼저 옮겨 묻게 하면 성능이 오르기도 한다. ([arXiv 2502.15603](https://arxiv.org/html/2502.15603v1))
- 번역에도 직역투가 남는다. GPT-4 번역의 40% 이상에서 직역투 오류가 나왔다. 그래서 영어로 먼저 쓰는 것만으로는 부족하고, 번역 단계에 자연스러움 지침과 검사가 필요하다. ([ACL 2025](https://aclanthology.org/2025.acl-long.630/))
- [Skill-Techblog](https://github.com/KANG-YEONWOOK/Skill-Techblog)(MIT)에는 한국어 문체 검사 스크립트(`lint_ko.py`, `patterns_ko.json`, `thresholds.json`)가 있다. 기준은 토스·카카오·당근 기술 블로그 224편을 측정해 정했다.

### 선택지

- **A (추천)** 영어를 정본으로 두고, 사람이 보는 것만 한국어로 번역한다.
  - 기억 단위, 작업 계약, 세션끼리 주고받는 문서는 영어로만 쓴다.
  - Slack 질문, 작업 의도 요약, 검토용 요구사항·기능 명세, 진행 보고는 영어로 쓴 뒤, 쓴 세션과 다른 세션이 한국어로 번역해서 보낸다. 번역 결과는 Skill-Techblog 검사 스크립트로 확인한다.
  - 사용자 답변 원문은 받은 언어 그대로 보존하고, 영어 정본 단위가 원문을 가리킨다.
  - 사용자가 한국어 번역본을 보고 고쳐 달라고 하면, 영어 정본을 고친 뒤 다시 번역한다.
- **B** A와 같되, 모든 문서의 한국어 사본도 레포에 함께 둔다. 정본이 바뀔 때마다 사본도 다시 번역해야 한다.
- **C** 한국어를 정본으로 둔다. 모든 문서를 영어 초안 → 번역 과정을 거쳐 한국어로 남기고, 에이전트도 한국어 문서를 읽는다(insight.md 문장을 글자 그대로 따르면 이쪽).

## 사용자 답변 (2026-10-06, 원문 그대로)

```text
A 로 해줘. 한국어로 써야하는 글은 영어원분 기반으로 Skill-Techblog 스킬을 사용해서 쓰면 돼. 그 스킬에 이미 작성과 검토까지 모든 flow가 있어.
```

## 선택지 대응 (요약, 원문이 우선)

- **A.** 영어가 정본이다. 사람이 보는 것만 한국어로 내보낸다.
- 한국어로 써야 하는 글은 영어 원문을 바탕으로 Skill-Techblog 스킬로 쓴다. 이 스킬에 작성부터 검토까지의 흐름이 모두 들어 있으므로, 별도의 번역 지침이나 검사 절차를 새로 만들지 않는다.
