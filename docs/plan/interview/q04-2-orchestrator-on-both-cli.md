# Q04-2. 오케스트레이터도 Claude와 Codex 모두에서

- 답변일: 2026-10-06
- 관련: [Q04](q04-target-cli.md), [Q03-3](q03-3-launcher-and-slack.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

말씀에 "오케스트레이터 **클로드** 세션"이라고 하셨고, Codex에는 `claude --bg` 같은 백그라운드 세션 기능이 확인되지 않는다. 그래서 Codex에서 skill을 실행해도 오케스트레이터는 Claude 세션으로 뜨는 게 자연스럽다. 이 경우 Q04의 "두 CLI 모두 지원"은 "skill은 두 CLI 어디서든 실행할 수 있고, 오케스트레이터는 Claude 세션, Codex는 작업 세션과 조언·교차 조사에 쓴다"는 뜻이 된다. 이렇게 이해하면 맞는가? Codex 세션도 오케스트레이터가 될 수 있어야 한다면 Codex용 세션 실행기를 따로 만들어야 한다.

## 사용자 답변 (2026-10-06, 원문 그대로)

```text
굳이 백그라운드 세션 아니어도 돼. Codex 용 세션 실행기 만드는 것도 좋아. 클로드 코덱스 모두 사용 가능한게 목표야.
```

## 요약 (원문이 우선)

- 오케스트레이터를 띄우는 수단이 Claude Code 백그라운드 세션(`claude --bg`)일 필요는 없다.
- Codex용 세션 실행기를 만든다.
- 목표는 Claude와 Codex를 모두 쓸 수 있는 것이다. 오케스트레이터도 두 CLI 어느 쪽이든 될 수 있다.

## 이 답에 따른 정리 (AI 분석, 원문이 우선)

- **두 CLI가 같은 실행기를 쓴다.** 세션은 이 레포의 `step2step`을 바탕으로 한 세션 실행기가 띄운다. Claude는 PTY로, Codex는 app-server로 띄운다. skill을 실행한 세션, 오케스트레이터, 다음 오케스트레이터는 모두 같은 실행기 명령으로 세션을 띄운다. `claude --bg`는 Claude 쪽에서 쓸 수 있는 선택지로 남긴다.
- **실행기가 세션을 쥐고 있으므로, Slack 답이 오면 실행기가 그 답을 새 턴으로 넣어 오케스트레이터를 깨울 수 있다.** Claude는 `SessionHandle.send`, Codex는 app-server의 새 턴을 쓴다. 그래서 [Q03-2](q03-2-bootloader-session.md)에서 걸렸던 "Codex는 한가한 세션을 깨울 방법이 없다"는 문제가 두 CLI 모두에서 같은 방식으로 풀린다.
- **spike에서 확인할 것:**
  - 실행기 프로세스가 skill을 실행한 세션이 끝난 뒤에도 계속 도는지(macOS에서 분리 실행)
  - `step2step` 보정이 현재 버전(Claude Code 2.1.291, codex-cli 0.155.1)에서 맞는지
  - Codex 오케스트레이터가 실행기 명령으로 다음 세션을 띄울 수 있는지
