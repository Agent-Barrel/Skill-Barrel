# Q15. 작업 트리와 작업 계약을 어디에 두는가

- 질문일: 2026-10-08
- 관련: 2026-09-29 초안 OD-5, [Q06](q06-task-tree.md), [Q07](q07-shared-memory.md), [Q12](q12-model-config-and-cli-fallback.md), [Q14](q14-parallel-sessions.md)
- 기록 원칙: 사용자 답변은 받은 그대로 적는다. 아래 "요약"은 찾아보기 편하도록 붙인 것이며, 내용이 다르면 답변 원문이 우선한다.

## 질문 (사용자에게 보낸 내용)

[Q13](q13-depth-by-impact.md), [Q16](q16-engines-and-verification.md)과 같은 메시지에서 물었다.

### 왜 지금 묻는지

- 앞서 정한 것: 기억은 레포 안에 두고 git으로 추적한다(Q07). 모델 배정은 `.barrel/` 안의 설정 파일로 팀과 공유한다(Q12).
- 아직 정하지 않은 것: 작업 트리와 말단 작업 계약의 위치다.
- Q14에서 정한 병렬 실행에서는 worktree 여러 개가 같은 계약을 읽으므로, 위치를 지금 정해야 한다.

### 다른 도구 조사 요약

- **명세 중심 도구는 계약 파일을 레포에 두고 커밋한다.**
  - Kiro는 `.kiro/specs/<기능>/tasks.md`를 커밋하라고 안내한다("you should commit these specification files").
  - Spec Kit은 `specs/`를 팀과 공유하고, 그 PC에서만 의미 있는 `feature.json`만 git에서 뺀다.
  - Taskmaster도 기본값이 git 저장이다.
- **CLI 내장 기능은 홈 폴더에 둔다.** Claude Code 작업 목록은 `~/.claude/tasks`, Codex `/goal`은 `~/.codex`에 저장한다.
- **레포에 둘 때의 문제:** 작업 파일끼리 병합 충돌이 나고, PC에서만 쓰는 값이 섞인다.

### 선택지

- **레포 .barrel/tasks/, git 추적 (추천)** 노드마다 파일 하나로 두고 기억, 설정과 함께 팀이 공유한다. 오래 남는 상태(계획됨, 완료와 커밋, 포기)만 적고, 진행 중·막힘·시도 횟수·세션 같은 순간 상태는 레포 밖 실행 상태에 둔다.
- **레포 밖 실행 상태** `~/.barrel/` 아래에 둔다. 레포는 깨끗하지만 팀이나 다른 PC와 공유되지 않고, 그 PC를 잃으면 트리도 잃는다.
- **레포 안, git 제외** `.barrel/tasks/`에 두되 `.gitignore`로 뺀다. 이 PC의 worktree들은 함께 보지만 팀과 공유되지 않는다.

## 사용자 답변 (2026-10-08, 원문 그대로)

선택지를 골랐다.

```text
레포 .barrel/tasks/, git 추적 (추천)
```

## 요약 (원문이 우선)

- 작업 트리와 작업 계약은 대상 레포의 `.barrel/tasks/`에 노드마다 파일 하나로 두고 git으로 추적한다. 기억, 설정과 함께 팀이 공유한다.
- 파일에는 오래 남는 상태(계획됨, 완료와 커밋, 포기)만 적는다.
- 진행 중, 막힘, 시도 횟수, 세션 같은 순간 상태는 레포 밖 실행 상태에 둔다.

## 이 답에 따른 정리 (AI 분석, 원문이 우선)
